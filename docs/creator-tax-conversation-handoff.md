# 1인 유튜버 세금 프로젝트 대화 인계

최종 정리일: 2026-10-19

## 최신 인계 요약 — 아래의 과거 미정 사항보다 우선

구현 담당자에게는 [단일 인계 명세](creator-tax-dummy-format.md) 하나만 전달한다. 더미 제작·PDF 형식·ML 요청/응답·화면 구분·DB 형식·완료 기준을 모두 포함한다. 이 파일은 과거 대화 기록용이다.

더미데이터 제작도 함께 인계한다. 세부 예시는 [더미데이터 형식](creator-tax-dummy-format.md)의 최신 인계 예시, 세금·시뮬레이션 기대값은 [정리 노트](creator-tax-notes.md)의 최신 인계용 결정·계산 기대값을 따른다.

| 단계 | 만들 것 | 기대 결과 |
| --- | --- | --- |
| 더미 제작 | 면세 1인 유튜버 업무 입출금·기본정보·분리된 정답 | PDF에는 카테고리 정답 미포함. 공제액은 본인 포함 총액과 설명 기재 |
| PDF | 단일 PDF, 세전 수입·차감 세금·실입출금 분리 | 예시 6건 추출, 현금 수입 1,947,000원·지출 409,000원·세전 수입 2,000,000원 |
| 분류 | TF-IDF + LogisticRegression / LinearSVC 비교 후 선정 | 모호한 물품 구매 50,000원은 미분류, 합계에는 포함 |
| 연결 | Spring 추출→FastAPI 분류→Spring→React 목록 | 날짜·금액 유지, 카테고리 추천 및 사용자 수정 가능 |
| 결과 | 월·카테고리 차트와 산출 근거 | 미분류 수정 후에도 총액 불변. 기본공제 중복 차감 없음 |
| 시뮬레이션 | 로그인 사용자만 추가 수입·업무 지출·적격 복지단체 기부 비교 | 기존 예상값에 중복 가산하지 않음. 초기화하면 기본 결과 복원 |

- 위 금액은 합계 검증용 예시값이며 실제 모델 출력·연간 예측값이 아니다.
- 현재 코드에는 PDF 추출·화면 반영 연결이 있고 ML 구현은 없다. 실제 실행은 미검증이다. 카테고리가 없는 행도 추출되도록 기존 파서를 수정해야 한다.
- 창업감면 대상 요건은 충족한다고 가정하는 것으로 결정했다. 가정을 화면에 표시하고 감면율·기간은 법령 확인 후 구현한다.
- 기부는 적격 복지단체로 한정한다. 한도·계산 방식은 법령 확인 항목이지 사용자 선택 사항이 아니다.
- 결과는 연간 예상 종합소득세다. 추가 납부·환급액 및 기납부세액 입력·조회 연동은 제외한다.
- 수입·지출 예측 방식은 미정이다. 개발 시작 전에 반드시 결정해야 한다. 1~12월 생성 후 기준일 이후를 평가용으로 분리하는 방식은 제작 제안이다.
- 아래에 남은 PDF 미정·모델 미선정·다중 자료·과거 Git 요청 등은 당시 이력이다. 현재 인계가 Git 전환·커밋·push를 승인하는 것은 아니다.

## 최신 정정 — 실제 입출금 기준

- 최신 화면 확정: 결과 조회는 비로그인 허용, 시뮬레이션 진입·계산·비교·저장은 로그인 전용. 노란우산 대신 기부 항목을 두며 확정 예정 수입·업무 지출·기부를 반영해 연간 예상 종소세를 비교한다. 기부 계산은 노란우산과 별도이며 검증 전이다. 확정 예정액과 기존 예측의 중복 방지가 필요하다. 결과 저장·회원가입 후 이어 저장 요구는 유지한다. 현재 문서 설계이며 코드 구현은 별도다.

- 최신 범위 변경: 추가 납부·환급 계산, 기납부세액 입력·조회 안내 후 수집·자동 연동은 제외한다. 결과는 연간 예상 종합소득세(기납부세액 차감 전)이며 시뮬레이션과 절세 팁이 핵심이다. 결과 저장·회원가입 후 이어 저장·로그인 전용 시뮬레이션은 유지한다. 아래의 과거 정산 관련 제안보다 이 결정을 우선한다. 지방소득세와 외국납부세액공제 지원 방식은 별도 미정이다.

- 최신 지원 범위: 면세 1인 미디어 콘텐츠 창작자(940306)부터 설계·검증한다. 과세 미디어콘텐츠 창작업(921505)은 시간 여유가 있을 때 확장한다. 기존 더미데이터 카테고리는 유지하며 1차 사례와 확장 사례를 구분한다.

- 올해 시작부터 특정 기준일까지 실제 발생한 업무 입출금 내역을 받는다. 일시불은 실제 출금 전액, 할부는 실제 회차 출금액을 기록한다.
- 원본을 전체 구매액으로 환산하거나 감가상각비로 바꾸지 않는다. 지출 집계와 미래 입출금 예측도 같은 기준이다.
- 장비는 이미 업무에 사용한 것으로 전제한다. 사용 시작일·이전 장부 등의 질문은 확정 요구사항이 아니다.
- '총 구매액 통일', '기존 감가상각비도 원본에 포함', '올해 신규 구매만 지원'은 어시스턴트의 오해·미채택 제안이다.
- 입출금 데이터와 세금 계산을 연결하는 방식은 미정이다. 현금 지출 전액을 법정 필요경비로 확정한 것은 아니다.
- PDF 추출은 다른 팀원, ML·계산·시뮬레이션·세무 정보·Elasticsearch는 사용자 담당이다.
- 아래는 이전 인계 기록이다. 이 절과 최신 노트의 확정 전제를 우선한다. 과거 Git 요청·작업 순서는 현재 실행 지시가 아니다.

## 사용자가 만들려는 서비스

- 1인 유튜버 대상이다. 기존 화면은 러프한 참고용이며 프리랜서용 예시 문구·세액을 확정 기준으로 사용하지 않는다.
- 수입·지출 내역을 받아 연중 언제나 연간 예상세액을 계산한다.
- 미래 광고 수입, 필수지출, 장비 구매, 기부 등 계획을 반영한 시나리오와 기본 결과를 비교한다.
- 사업자등록과 과세 유형별 장단점·의무도 설명하려 한다. 단순히 등록 버튼을 바꾸면 절세된다고 가정하지 않는다.
- 오늘 정리하려던 세 가지는 필요한 데이터, 계산식, ML 활용 방법이다. 아직 모두 확정하지 않았다.

## 대화 방식과 작업 요청

- 사용자는 세무 개념을 큰 틀부터 하나씩 이해하고 싶어 한다. 긴 설명·많은 예외를 한꺼번에 나열하면 혼란스러워했다.
- 대화 중 이해한 내용은 노트에 계속 기록하고, 잘못 안 내용은 본문도 수정한다.
- 조사 링크·확인일·적용연도·최신성 확인 상태를 남긴다. 과거 자료를 최신이라고 단정하지 않는다.
- 대용량 데이터를 통째로 출력하지 않는다. 목록·컬럼·첫 4~5건과 짧은 판단만 제시한다.
- 현재 요청은 작업 중단 전 두 문서를 docs에 보관하고 feature/khs에 푸시하는 것이다. PR·merge 요청은 없다.

## 핵심 개념과 정정

- 수입은 비용을 빼기 전 금액이다. 실제 입금액과도 구분한다.
- 실제 장부 기준 사업소득금액은 총수입금액에서 필요경비를 뺀 금액이다.
- 종합소득세는 세금의 한 종류다. 원천징수와 정산한 차액만을 뜻하지 않는다.
- 해당 지급액의 3.3% 원천징수는 미리 낸 소득세·지방소득세이며, 유튜버 수입 전체의 최종 세율이 아니다.
- 최종 세액과 기납부세액을 구분해야 추가 납부 예상액을 계산할 수 있다. 기납부액 모름을 0원으로 처리하지 않는다.
- 공제는 모든 사람에게 고정 적용되는 금액이 아니다. 항목별 요건·한도와 개인 조건이 있다.
- 등록 의무, 부가세 과세·면세, 종소세, 건강보험 피부양자 자격을 섞지 않는다.
- 건강보험은 세금이 아니며, 피부양자 유지를 이유로 등록 의무를 무시하도록 안내하지 않는다. 최신 피부양자 규칙 검증은 남아 있다.

## 현재 가장 많이 논의한 지출 분류

사용자는 업무 관련 실제 입출금 내역을 입력한다. 세무 조정이 완료된 장부라는 뜻이 아니다.

- 용도 분류: 택시·버스·지하철 → 교통비. 사용자가 제안한 분류 ML이다.
- 세무 처리: 일반 비용 후보 / 자산 구입 후보 / 별도 확인 항목. 서비스 설계안이지 법정 분류가 아니다.
- 인정된 경비는 합산해 수입에서 빼지만, 장비 등은 올해 얼마를 반영할지 별도 규칙이 필요하다. 모든 장비를 반드시 감가상각한다고 단정하지 않는다.
- 업무용 장부에 이미 계정과목이 있으면 다시 분류할 필요가 적다. 분류 없는 입력을 지원하는지, 계정과목을 통일하는 기능인지 먼저 결정한다.

## 데이터 조사 결과

### 처음 제공한 압축 두 개

- 금융신용 합성데이터 압축과 data.zip을 확인했다. 신용·대출·연체 지표 중심이라 우리 수입·지출 장부 용도로 맞지 않았다.
- 개인 수입·지출 거래 날짜·금액·설명이 필요하다. 신용 분석용 데이터를 활용하려고 목표를 바꾸지 않는다.

### 해외 거래 분류 후보

- [DoDataThings/us-bank-transaction-categories-v2](https://huggingface.co/datasets/DoDataThings/us-bank-transaction-categories-v2): 제공자 설명상 영어 합성 거래 68,000건·17개 분류. 거래 설명·정답 분류 중심이다.
- [mitulshah/transaction-categorization](https://huggingface.co/datasets/mitulshah/transaction-categorization): 약 450만 건·10개 분류, 거래 설명·분류·국가·통화. 해외·합성 포함, 접근 조건 동의 필요.
- 첫 후보는 공개 뷰어 첫 5건, 두 번째는 설명서 예시 5건만 확인했다. 전체 다운로드는 하지 않았다.
- 한국 유튜버 업무용 주 학습데이터로 바로 쓰기에는 맞지 않아 구조 참고·보완 실험용으로 보류했다. 날짜·금액·개인별 연속 이력이 없어 미래 금액 예측 자료도 아니다.

### 사용자가 붙여넣은 Google 생성 표

- 사용자가 ‘1인유튜버 수입지출내역 더미데이터’라고 물어 얻은 수입 18건·지출 24건의 2026년 표를 전달했다.
- 수입 예: 애드센스, 협찬, 멤버십, 강연료, 굿즈 판매. 지출 예: 프로그램 구독, 장비, 편집 외주, 스튜디오, 소품, 광고, 기장 수수료.
- 화면·PDF·기본 계산 시연용 초안으로 적합하지만 실제 관측 자료라는 근거는 없다. Google이 YouTube를 운영한다는 사실이 생성 답변의 정확성을 보증하지 않는다.
- ‘강연료 기타소득(3.3%)’ 표기는 정정 필요. 일시·계속적 활동에 따른 소득 구분과 원천징수를 대조해야 한다.
- 멤버십·애드센스 중복, 외주비의 세전/실지급액, 본인이 낸 원천세와 남에게 지급하며 뗀 세금, 연납 비용 기간, 장비 처리, 겸업·업종 등을 확인해야 한다.
- 42건으로 ML 학습·현실 예측 정확도를 입증할 수는 없다. 원본 생성 답변 URL은 전달받지 못했다.

## PDF·OCR·ML

- 사용자는 PDF 입력이 맞는 것 같다고 했다. 최종 지원 문서 양식은 미정이다.
- PDF 추출과 카테고리 ML은 다른 단계다. 학습 데이터는 정형 표로 보관해도 된다.
- 표 데이터로 가상 PDF를 만들어 추출 결과와 대조할 수 있다. 분류 모델 입력에는 정답 카테고리를 노출하지 않는다.
- 합성 자료는 코드로 파일 생성하면 행별 대화 생성보다 토큰을 줄일 수 있다. 템플릿 암기·학습/평가 중복을 주의한다.
- 세금 계산은 규칙 기반, ML은 지출 분류와 자료 확보 후 미래 금액 예측 후보로 둔다. 모델은 아직 선정하지 않았다.

### TJK-5 확인 결과

- 브랜치를 전환하지 않고 로컬 원격 추적 참조 origin/feature/TJK-5를 읽었다. 마지막 확인 커밋은 cb67071이다. 원격 fetch는 하지 않았다.
- PDFBox·Tess4J 의존성, 한국어·영어 OCR 설정, TaxOcrService.extract 호출이 있다.
- 그 참조의 추적 파일에서 TaxOcrService 구현을 찾지 못했고 TaxValidator 참조도 대조가 필요했다. 실행 완성 여부는 미확인이다.
- 현재 feature/khs에는 스캔 PDF OCR 미지원 메시지가 있다. 새 OCR을 전제로 개발하지 말고 TJK-5 최신 작업과 필요 환경부터 재확인한다.

1. feature/khs의 최신 문서 두 개를 받고 이 인계와 노트를 읽는다.
2. 실제 입력할 PDF가 카드 명세서인지, 업무용 장부인지, 계정과목까지 있는 문서인지 정한다.
3. 지원 귀속연도·업종·개인 조건을 좁히고 경비·공제·기납부 처리 규칙을 공식 자료와 대조한다.
4. Google 생성 표의 오류를 바로잡아 작은 검증용 거래 표를 만든다. 아직 원본 표 파일이나 PDF는 만들지 않았다.
5. 카테고리 ML의 입력·정답과 역할을 결정하고 학습용 다양성을 확보한다.
6. TJK-5 최신 OCR 구현을 확인한 뒤 PDF 추출과 연결한다.

## Git·환경 상태

- 작성 브랜치: feature/khs. 다른 브랜치로 전환·merge하지 않았다.
- 이 작업의 대상: 이 인계 파일과 creator-tax-notes.md 두 개뿐이다.
- 루트 package-lock.json이 별도 미추적 파일로 있었으며 이번 문서 작업에 포함하지 않는다.
- 문서 저장·푸시용 티켓 번호는 사용자에게서 전달받지 않았다. 임의의 TJK 번호를 만들어 붙이지 않는다.
- 세무 자료 열람일·최신성·미검증 항목은 정리 노트의 출처 표를 참조한다.
