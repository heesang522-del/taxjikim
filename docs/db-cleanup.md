# 미사용 DB 정리 (2026-11-10)

## 확인 결과

| 대상 | 코드 확인 결과 | 정리 내용 |
| --- | --- | --- |
| `users.BIRTH_DATE` | 회원가입 화면·상태·검증·요청, `UserDto`, 회원 가입·조회·수정 Mapper에서 제거 | 새 DB 생성 SQL에서 컬럼 제거. 기존 DB는 컬럼 삭제 |
| `USER_SANCTIONS` | 실행 코드의 조회·저장·수정·삭제 참조 없음 | 생성 정의와 해당 테이블의 외래키 정의 제거. 기존 DB는 테이블 삭제 |
| `USER_LOGIN_SECURITY` | 실행 코드 참조 없음. `LoginAttemptServiceImpl`에서 Redis와 Lua로 실패 횟수·일시 차단 관리 | 생성 정의와 해당 테이블의 외래키 정의 제거. 기존 DB는 테이블 삭제 |
| `tax_process_logs` | 업로드·계산·관리자 실행 코드에서 참조 없음 | 생성 정의와 내부 외래키 정의 제거. 기존 DB는 테이블 삭제 |

현재 회원 테이블의 실제 이름은 `USER`가 아니라 `users`다. 로그인 계정 잠금은 `users.USER_STATUS`에도 반영하므로 이 컬럼과 관련 로직은 유지한다. 신고 처리는 `REPORTS`를 사용하므로 유지한다.
제거할 테이블 전용 메서드는 실행 코드에서 발견되지 않아 추가로 삭제할 메서드는 없다.

## 변경 파일

- `back/local/schema.sql`: 새 로컬 DB용 생성 정의. 기존 DB에 다시 실행하는 마이그레이션이 아니다.
- `docs/db-cleanup.sql`: 기존 DB에서 수동 실행할 사전 확인·삭제·사후 확인 SQL.
- `docs/user-birth-date-migration.md`: 생년월일 제거의 코드 적용 순서와 기존 컬럼 안내.
- `docs/creator-tax-dummy-format.md`, `front/docs/api-draft.md`: 현재 사용하지 않는 테이블을 사용하는 것처럼 설명한 내용 정리.

## 기존 DB 적용 순서

1. 대상 DB와 백업을 확인한다. 삭제할 컬럼·테이블의 데이터는 삭제 후 일반적인 트랜잭션 롤백으로 복구할 수 없으므로 필요한 데이터는 먼저 보관한다.
2. 생년월일 참조를 제거한 새 프론트·백엔드를 적용한다. 이전 버전 서버를 종료한다.
3. `db-cleanup.sql`의 사전 확인 구간만 실행한다. 실제 테이블 이름·대소문자, 외부에서 들어오는 외래키, 뷰·트리거·이벤트·프로시저 의존성을 확인한다. 저장소에서는 실제 DB 객체와 다른 프로그램의 사용 여부를 확인하지 못했다.
4. 외부 의존성이 남아 있으면 삭제 구간을 실행하지 말고 해당 객체를 먼저 확인한다. 외래키 검사를 끄고 강제 삭제하지 않는다.
5. 확인한 실제 이름에 맞춰 삭제 구간을 수동 실행한다. 컬럼이 이미 삭제됐다면 ALTER 문은 건너뛴다. 테이블 자신의 외래키는 테이블 삭제와 함께 제거된다.
6. 사후 확인 SQL과 회원가입·로그인·관리자 잠금 해제·신고·세금 분석 흐름을 확인한다.

이 작업에서는 실제 DB에 접속하거나 삭제 SQL을 실행하지 않았다.
