# 예상세액 계산 기준

## 2026-10-30 입력·DB 변경 합의

- 면세 1인 유튜버 기본 계산에서 창업감면을 제외한다. `AGE`, `STARTUP_RELIEF_APPLIED`, `BUSINESS_REGION`을 제거하며 `BUSINESS_REGISTERED`는 안내 구분용으로 유지한다.
- 특례기부금과 일반기부금(종교단체 제외)을 GENERAL_DONATION_AMOUNT·SPECIAL_DONATION_AMOUNT로 구분한다. 일회성 변경 SQL은 사용자 요청으로 삭제했다.

- 아래의 나이·창업일·지역 입력에 관한 이전 기록보다 이 합의를 우선한다.

정리일: 2026-10-22. 사용자 합의와 법규 확인 상태를 관리한다. 구현 완료나 올해 세법 검증 완료를 의미하지 않는다.
전체 연결·API·DB는 [전체 명세](creator-tax-dummy-format.md)를 따른다.

## 총세금·산출 근거 공통 계산 기준 (2026-10-30 합의)

테스트 분석번호는 사용자가 변경한 `21`이다. 번호는 계산식의 일부가 아니며 실제 전달 연결 시 고정값을 제거한다. 아래는 구현 전 계산 설계이며, 실행 코드를 수정한 것은 아니다.

### 전제

- 사업소득만 있는 면세 1인 유튜버의 예상 계산이다. 일반 지출 전액을 당해 필요경비로 가정한다.
- 총수입·총지출은 기존 월별 서비스를 통해 실제·예상 금액을 포함해 받는다.
- 기부금은 일반 지출에서 제외한 별도 입력값이다. 두 기부금과 가족 수를 월평균으로 늘리지 않는다.
- 가족 수는 기본공제 요건을 충족한 본인 외 인원이다. 기본공제는 본인을 포함해 계산한다.
- 과거 적자(이월결손금)는 지원 범위에서 제외한다.
- 과거 기부금은 신고서에서 확인한 미공제 이월잔액을 사용자가 직접 입력하는 방향이다. 올해 기부금에 단순 합산하지 않으며 유형·발생연도 등 필요한 입력과 DB 연결은 후속 구현한다. 아래 기본 계산과 더미 예시는 이월잔액 0원 기준이며, 이월기부금 기능이 구현된 것으로 표시하지 않는다.
- 표준세액공제는 일반 기준인 연 70,000원을 적용한다. 성실사업자 여부를 추가 입력받거나 자동 판정하지 않는다.
- 창업감면·기납부 원천징수 차감·추가 납부액·환급액은 제외한다.

### 계산 순서

`min`은 두 값 중 작은 값, `max(0, 값)`은 음수이면 0으로 처리한다는 뜻이다.

```text
① 기부금 반영 전 사업소득 = 총 세전 수입 - 총지출
   기부금 한도용 기준금액 = max(0, ①)

② 특례기부금 인정액 = min(특례기부금 입력액, 기준금액)
   ※ 개인사업자의 특례기부금 한도. 법인에 적용하는 50%와 혼동하지 않는다.

③ 일반기부금 한도 = max(0, 기준금액 - 특례기부금 인정액) × 30%
   일반기부금 인정액 = min(일반기부금 입력액, 일반기부금 한도)
   ※ 종교단체 기부가 없는 이번 지원 범위 기준.

④ 기부금 반영 후 사업소득 = ① - 특례기부금 인정액 - 일반기부금 인정액

⑤ 기본공제액 = (본인 1명 + DEPENDENT_COUNT) × 1,500,000원

⑥ 과세표준 = max(0, ④ - 기본공제액)

⑦ 종합소득 산출세액 = 과세표준 × 해당 구간 세율 - 누진공제액

⑧ 표준세액공제 적용액 = min(산출세액, 70,000원)
   종합소득 결정세액 = max(0, 산출세액 - 70,000원)

⑨ 개인지방소득세 = 종합소득 결정세액 × 10%
   ※ 이번 서비스의 기본 예상 계산 방식. 최종 끝자리 처리는 구현 전에 확인.

⑩ 화면의 총세금 = 종합소득 결정세액 + 개인지방소득세
```

화면 안내: “법정 성실사업자 요건을 충족하면 표준세액공제가 12만원으로 늘어나, 소득세가 최대 5만원 더 줄어들 수 있습니다.” 실제 계산은 7만원 기준이며 세금이 0원 미만으로 내려가거나 공제 차액을 환급받는 것으로 표시하지 않는다. 성실사업자는 단순히 문서를 작성하거나 사업자등록을 한 사람을 의미하지 않는다.

지방소득세는 사업소득에 대한 개인지방소득세이며 취득세·자동차세와 구분한다. 사용자에게 부동산·차량 취득 내역이나 지역 정보를 추가로 받지 않는다. 법정 계산은 별도 지방소득세율·공제 규칙을 따르지만 이번 지원 범위에서는 위 10% 방식으로 예상한다. 원천징수된 세금의 10%를 가져오는 방식이 아니다.

### 종합소득세 기본세율

| 과세표준 | 세율 | 누진공제액 |
| --- | --- | --- |
| 1,400만원 이하 | 6% | 0원 |
| 1,400만원 초과 ~ 5,000만원 이하 | 15% | 126만원 |
| 5,000만원 초과 ~ 8,800만원 이하 | 24% | 576만원 |
| 8,800만원 초과 ~ 1억 5,000만원 이하 | 35% | 1,544만원 |
| 1억 5,000만원 초과 ~ 3억원 이하 | 38% | 1,994만원 |
| 3억원 초과 ~ 5억원 이하 | 40% | 2,594만원 |
| 5억원 초과 ~ 10억원 이하 | 42% | 3,594만원 |
| 10억원 초과 | 45% | 6,594만원 |

### 더미 데이터 산술 대조 (예시값)

- 연간 실제·예상 세전 수입: 60,000,000원 / 지출: 12,000,000원
- 기부금 반영 전 사업소득: 48,000,000원
- 특례기부 300,000원: 한도 내 전액 인정
- 일반기부 한도: (48,000,000 - 300,000) × 30% = 14,310,000원
- 일반기부 500,000원: 한도 내 전액 인정
- 기부금 반영 후 사업소득: 47,200,000원
- 본인·공제 가족 1명의 기본공제: 3,000,000원
- 과세표준: 44,200,000원
- 종합소득 산출세액: 44,200,000 × 15% - 1,260,000 = 5,370,000원
- 표준세액공제 적용액: 70,000원
- 종합소득 결정세액: 5,370,000 - 70,000 = 5,300,000원
- 개인지방소득세: 5,300,000 × 10% = 530,000원
- 총세금: 5,300,000 + 530,000 = 5,830,000원
- 모두 예시 데이터의 예상 계산값이며 실제 추가 납부액·환급액이 아니다. 이 예시는 끝자리가 정수이므로 절사 규칙 확정으로 인한 차이가 없다.

### 계산 결과에 남길 값

총수입, 총지출, 기부금 반영 전후 사업소득, 유형별 기부금 입력액·한도·인정액·한도초과액, 기본공제액, 과세표준, 적용세율, 누진공제액, 산출세액, 세액공제액, 결정세액, 지방소득세, 총세금. 같은 결과 DTO를 총세금 카드와 산출 근거에서 공유한다.

### 하나씩 구현할 순서

1. 분석번호로 공제 대상 가족 수·특례기부금·일반기부금을 읽는다. 기존 총수입·총지출 서비스 결과를 사용한다.
2. 기부금 반영 전 사업소득을 계산한다.
3. 특례기부금 인정액을 계산한다.
4. 일반기부금 한도·인정액과 기부금 반영 후 사업소득을 계산한다.
5. 본인·가족 기본공제와 과세표준을 계산한다.
6. 세율·누진공제로 산출세액을 계산한다.
7. 표준세액공제 7만원을 적용한다.
8. 끝자리 규칙 확인 후 지방소득세·총세금을 계산한다.
9. 같은 계산 결과 DTO를 총세금 카드와 산출 근거에서 사용한다. 통합 결과 조회 구조는 이후 별도 티켓에서 진행한다.

각 단계는 사용자와 문서를 확인하며 차례대로 작성한다. 이 문서 수정만으로 계산 코드가 구현된 것은 아니다.

### 현재 구현: 계산 입력 조회

①~④는 `TaxServiceImpl`의 내부 메서드 `calculateDonations(input)`에 구현했다. 이미 조회한 입력 DTO를 받아 특례 인정액 → 일반 한도·인정액 → 기부금 반영 후 사업소득 순으로 계산한다. 별도 기부금 조회 API나 추가 DB 조회는 없다. 이후 전체 계산 흐름에서 호출하도록 연결할 예정이며, 현재 입력 조회 API에서는 실행하지 않는다.

내부 계산 결과는 산출 근거용 `TaxBreakdownDto`에 담는다. 기부금만을 위한 DTO나 시험용 DTO를 단계마다 만들지 않고, 이후 기본공제·과세표준·세금 결과도 이 DTO에 추가한다. 더미 입력 기준 반영 전 48,000,000원, 특례 인정 300,000원, 일반 한도 14,310,000원, 일반 인정 500,000원, 반영 후 47,200,000원이다. 기부금 한도의 원 미만 처리 확정 전에는 BigDecimal 계산값을 그대로 유지한다. DB 결과 저장이나 기본공제 이후 계산은 아직 하지 않는다.

`TaxService.getCalculationInput(taxInputId)`에서 `tax_inputs`의 귀속연도·공제 가족 수·두 기부금액을 조회하고, 기존 `getTotalIncome`·`getTotalExpense`의 실제·예상 합계를 `TaxCalculationInputDto`에 담는다. 분석이 없으면 조회 오류를 반환한다.

기존 `TaxApiController`의 `GET /api/v1/tax/inputs/{taxInputId}/calculation-input`으로 조회한다. Postman에서는 `GET http://localhost:8080/api/v1/tax/inputs/21/calculation-input`을 사용하며 Body는 비운다. 공통 응답의 `data`에 taxYear·dependentCount·specialDonationAmount·generalDonationAmount·totalIncome·totalExpense가 반환된다. 아직 세금 계산식이나 프론트 연결은 추가하지 않았다.

## 확정 범위

- 면세 1인 유튜버의 사업소득을 대상으로 사업자등록·미등록 사용자 모두 지원한다.
- 적용연도는 현재 연도다. 과거 세율·경비율 예시를 올해 값으로 간주하지 않는다.
- 결과는 연간 예상 종합소득세다. 기납부세액 차감과 추가 납부·환급 계산은 제외한다.
- 카테고리 분류는 ML, 세금 계산은 규칙으로 처리한다.
- 결과 조회는 비로그인도 허용한다. 계정에 결과 저장·시뮬레이션은 로그인 후 제공한다.

## 입력·계산 기준

| 항목 | 합의한 기준 |
| --- | --- |
| 수입 | 세전 수입으로 세금을 계산한다. 실제 입출금액과 원본의 차감 세율은 별도로 유지한다. 차감 세율을 연간 세액의 세율로 사용하지 않는다. |
| 지출·경비 | 업무 거래의 실제 출금액을 합산한다. 할부는 해당 회차 출금액을 사용한다. 실제 지출에 단순경비율을 적용해 일괄 상한을 만들지 않는다. |
| 기본공제 | 본인을 제외하고 기본공제 요건을 충족하는 가족 수를 받는다. DB에는 DEPENDENT_COUNT만 저장하고, 본인 공제와 가족별 공제액은 계산 로직에서 반영한다. |
| 기부금 | 특례기부금과 일반기부금(종교단체 제외)을 지원한다. 영수증상 유형으로 구분하며 유형별 인정 한도를 적용한다. 정치자금·고향사랑·우리사주조합·종교단체 기부금은 이번 지원 범위에서 제외한다. |
| 미래 수입·지출 | 우선 평균 방식으로 채운다. 평균 기간과 예정액 중복 처리 등 세부 설계는 이후 논의한다. |

업무 출금 전액을 당해 경비로 반영하는 것은 프로젝트 단순화 가정이다. 감가상각·개별 경비 한도 등 법정 처리 전체를 구현했다는 뜻은 아니며 결과에 가정을 안내한다.
기본공제·기부금은 서로 다른 항목이다. 일반 지출에 포함된 기부금은 분리해 한 번만 반영한다.
공제 설명·공제액은 별도 컬럼으로 저장하지 않는다. PDF에 공제 총액을 싣는 전체 명세의 사례는 계산 대조용 예시이며 최신 저장 입력은 가족 수다.

## 기부금 후속 작업 메모 (2026-10-30)

- 일회성 로컬 변경 SQL은 정리하여 삭제했다. 현재 컬럼 구조를 기준으로 구현하며 DB에 직접 변경을 실행한 것은 아니다.
- 저장 컬럼은 GENERAL_DONATION_AMOUNT와 SPECIAL_DONATION_AMOUNT로 구분한다. 변경 SQL은 기존 DONATION_AMOUNT 값을 일반기부금으로 유지하므로 특례기부금이 섞여 있다면 별도 재분류한다.
- [ ] 입력 화면 수정이 가능해지면 두 금액의 입력을 구분하고, 기부금 영수증의 유형을 확인하도록 안내한다. 입력 화면 수정은 현재 보류한다.
- [ ] 계산과 산출 근거에 유형별 입력액·인정액을 반영하고, 일반 지출과 중복 차감하지 않는다.
- 면세 1인 유튜버 기본 계산에서는 창업감면을 제외한다. AGE·STARTUP_RELIEF_APPLIED·BUSINESS_REGION을 제거하고 사업자등록 여부만 유지한다. 입력창은 PR 반영 후 수정한다.
- 등록 사용자 대상 사업 확장 팁에서 과세 미디어콘텐츠 창작업의 감면 검토 요건을 안내한다. 외주비 사용이나 과세 전환만으로 자동 적용되는 혜택으로 표현하지 않는다.

## 창업감면·정보 저장

> 아래는 이전 설계 기록이다. 2026-10-30 합의에 따라 기본 계산의 창업감면은 제외하며, 입력 화면·관련 문서는 PR 반영 후 정리한다.

- 미등록 사용자는 나이를 받아 등록 시 참고할 절세 정보를 제공한다. 거주지역은 필수로 받지 않는다.
- 등록 사용자는 계산 대상 연도에 창업감면을 적용받는지 확인하고, 적용하는 경우 창업일·창업 사업장 지역을 받는다.
- 대상임을 확인받은 흐름에서 나이를 다시 필수로 요구해 자격 심사를 반복하지 않는다.
- 현재 나이·창업 당시 나이, 거주지·사업장 지역을 혼동하지 않는다.
- 회원이 작성한 정보는 저장해 다음 계산에 불러오고 수정할 수 있게 한다. 비회원은 임시로 사용한다.
- 사용자 확인은 시스템의 법적 자격 검증 완료를 뜻하지 않는다. 940306의 감면 가능성은 공식 업종 해석과 대조하고, 대상이라고 가정한 시뮬레이션은 전제를 표시한다.
- 창업 시점·지역에 맞는 감면율을 적용한다. 최초 소득 발생 연도 등은 적용기간을 시스템이 직접 판정하는 범위에서 필요성을 검토한다. 올해 적용 여부를 확인받는 흐름과 혼동하지 않는다.

## 계산 순서

```text
실제 세전 수입 + 남은 기간 예상 수입
→ 업무 경비 차감 → 한도 내 기부금 반영
→ 기본공제 등 소득공제 → 과세표준
→ 올해 세율·누진공제 → 적용 가능한 감면·세액공제
→ 연간 예상 종합소득세와 산출 근거
```

- 미확인 금액은 0원과 구분한다. 세전 금액이 없다고 고정 세율로 역산하지 않는다.
- 기부금 전액이 소득 계산에 반영되는 것과 기부액만큼 세금이 줄어드는 것은 다르다.
- 실제와 예상을 구분하고 평균에 반영한 예정 거래를 시뮬레이션에서 중복 가산하지 않는다.
- 기존 프론트의 원천징수 차감·노란우산 계산식을 사용하지 않는다. 최신 계산 기준은 위의 공통 계산 기준을 우선한다.

## 후속 기능에 남길 참고

- 사업자등록 절세 팁은 미등록 사용자에게 제공한다. 등록 자체가 자동으로 세금을 줄인다고 표시하지 않는다.
