# 1인 크리에이터 예상세액 정리 노트

작성일: 2026-10-18
최종 대화 반영일: 2026-10-19

대화에서 확인한 개념을 쉽게 정리하는 작업 문서다. 완성된 세금 계산 명세는 아니며, 세부 적용 조건은 아래 확인 목록에서 계속 정리한다.

## 기록 방식

### 최신 인계용 결정·계산 기대값 (2026-10-19)

- 최신 카테고리 변경: 사용자 결정으로 수입에 외부 후원, 지출에 통신비를 추가한다. 장비는 하드웨어·소프트웨어로 구분한다. 유튜브 플랫폼 안의 후원은 플랫폼 정산에 포함해 외부 후원과 중복 집계하지 않는다. 미분류는 기존 통합 거래 목록의 카테고리 값으로 유지한다. 과거 외부 후원·통신비 제외 기록은 이 결정으로 대체한다.

전체 구현 인계는 [단일 인계 명세](creator-tax-dummy-format.md) 하나를 전달한다. 이 노트는 대화·계산 검토 기록이다.

이 절은 아래의 과거 논의보다 우선한다. PDF·분류·차트의 구체적인 예시와 기대 합계는 [더미데이터 형식](creator-tax-dummy-format.md)의 최신 인계 예시를 따른다. 실제 구현 완료 보고가 아니다.

**최신 합의**

- PDF 한 개에 기준일까지의 거래와 기본정보를 넣는다. 내부 CSV 제작은 사용자에게 CSV 작성·추가 업로드를 요구하는 뜻이 아니다.
- 기본공제는 PDF에 본인 포함 총액과 사유를 기재하고 그대로 사용한다. 가족 수를 추가 질문하거나 본인 공제를 다시 더하지 않는다.
- 업무 출금액 전액을 당해 경비로 반영하는 프로젝트 단순화 가정을 표시한다. 원본 할부 출금액을 전체 구입가로 바꾸지 않는다.
- 창업감면은 대상 요건을 충족한다고 가정하는 사용자 결정이다. 화면에 가정을 표시하고 적용 감면율·기간·순서·한도는 공식 법령 확인 후 구현한다.
- 기부는 기부금영수증 발급이 가능한 적격 복지단체로 한정하고 명시한다. 사업소득만 있는 사례의 인정 한도·필요경비 규칙을 적용하며 다른 경비와 중복 차감하지 않는다.
- 결과는 연간 예상 종합소득세이며 추가 납부·환급 계산은 제외한다. 자료의 차감 세금을 기납부세액으로 자동 차감하지 않는다.
- 결과는 비로그인 조회 가능, 시뮬레이션은 로그인 사용자만 진입·계산·비교·저장 가능하다. 비로그인 결과 저장은 가입·인증 후 원래 결과를 유지해 진행한다.
- 수입·지출 예측 방식은 미정이다. 개발 시작 요청이 오면 반드시 먼저 결정하도록 짚는다.

**연간 집계 계산 예시 — 모든 금액은 예시값**

PDF 예시 6건과 별개의 연간 집계 사례다. 아래는 국세청 표의 명시 범위인 2023~2025년 세율을 사용한 산술 검증이다. 서비스 대상은 현재 연도이며 이 표를 2026년 서비스 규칙으로 확정했다는 뜻은 아니다. 기부·창업감면·기타 세액공제 전 중간값부터 검증한다.

| 단계 | 계산 | 기대 결과 |
| --- | --- | ---: |
| 세전 연간 수입 | 전체 거래 검수 후 합계 | 50,000,000원 |
| 업무 경비 | 전액 반영 가정 | 20,000,000원 |
| 기본 사례 인정 기부금 | 기부 없음 | 0원 |
| 사업소득 | 50,000,000−20,000,000 | 30,000,000원 |
| 기본공제 | PDF 총액: 본인·적격 부양가족 각 1명이라는 예시 설명 | 3,000,000원 |
| 과세표준 | 30,000,000−3,000,000 | 27,000,000원 |
| 산출세액 | 27,000,000×15%−1,260,000 | 2,790,000원 |

산출 근거에는 수입·경비·기부 인정액·기본공제액과 사유·과세표준·세율·누진공제·감면액을 순서대로 표시한다. 2,790,000원은 감면 전 산출세액이며 최종세액으로 표시하지 않는다. 최종 예상세액은 확인된 창업감면·세액공제와 한도를 적용한 후 확정한다. 미확인 감면을 0원으로 조용히 처리하지 않는다. 외국납부세액공제 등 별도 세액공제의 지원 여부도 위 중간값과 구분해 확인한다.

출처: [국세청 세율표](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7667&mi=2224), 2026-10-19 확인. 표시 귀속연도와 적용연도 대조 필요. [기부금 필요경비 규정: 소득세법 제34조](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1033239627). 기부 한도는 단체 이름만으로 판단하지 않고 적격 여부·기부금 유형에 맞게 확인한다.

**시뮬레이션 기대값 — 위 사례에서 각각 독립 실행**

| 추가 입력 | 변경 후 과세표준 | 감면 전 산출세액 | 기준 대비 변화 |
| --- | ---: | ---: | ---: |
| 세전 수입 1,000,000원 | 28,000,000원 | 2,940,000원 | +150,000원 |
| 업무 지출 1,000,000원 | 26,000,000원 | 2,640,000원 | −150,000원 |
| 기부 1,000,000원, 전액 인정되는 테스트 전제 | 26,000,000원 | 2,640,000원 | −150,000원 |
| 모든 추가 입력 0원 / 초기화 | 27,000,000원 | 2,790,000원 | 0원 |

- 기부 전액 인정은 한도 모듈이 반환한 값을 검증하는 전제이지 실제 모든 기부가 전액 인정된다는 규칙이 아니다.
- 최종 화면의 세금 변화는 감면·세액공제까지 동일한 규칙으로 재계산해 비교한다. 위 표는 감면 전 중간값 검증용이다.
- 추가 금액은 기존 예상 대비 추가분이다. 기존 거래·예정액·예측값에 포함된 금액을 중복해서 더하지 않는다.
- 추가 지출·기부는 현금 1,000,000원이 나간다. 감면 전 세금이 150,000원 줄어도 1,000,000원 이득으로 표시하지 않는다. 추가 세전 수입의 실제 입금액은 차감 정보 없이 동일 금액으로 확정하지 않는다.
- 비로그인은 시뮬레이션 화면과 API 모두 로그인 필요. 로그인 후 입력·기준 결과를 유지한다. 저장 후 다시 열면 입력·계산 기준·결과가 일치해야 한다.

**현재 구현과 인계**

2026-10-19 현재 폴더의 코드에서 PDF 업로드→Spring 추출→React 목록 반영 연결을 확인했으나 실제 전체 실행은 검증하지 않았다. 현재는 카테고리 문자열 파싱이며 ML 구현·FastAPI 추론 연결은 없다. PDF에 카테고리가 없는 거래도 추출하도록 수정해야 한다. 더미 제작·PDF 변환·정답자료·TF-IDF + LogisticRegression / LinearSVC 비교·추론 연결까지 함께 인계한다. 수입 출처 시각화와 수입 분류 ML 구현 범위는 구분한다.

### 기존 기록 방식

- 앞으로 관련 대화에서 이해한 내용과 결정 사항을 이 파일에 이어서 반영한다.
- 잘못 이해한 내용은 본문을 올바른 설명으로 수정한다. 주요 정정은 아래 표에 남긴다.
- 공식 자료로 확인한 사실, 서비스 설계 제안, 추가 확인이 필요한 내용을 구분한다.
- 숫자·적용 조건에는 출처와 적용연도를 확인한다. 확인되지 않은 조건은 계산 규칙으로 확정하지 않는다.
- 조사한 내용에는 직접 확인 가능한 출처 링크, 열람일, 자료에 적힌 적용연도·개정일, 최신성 확인 상태를 함께 기록한다. 열람일과 법령 시행일을 혼동하지 않는다.
- 설명은 큰 개념부터 한 항목씩 진행한다. 현재 우선순위는 세금 계산 이해이며, ML 모델과 상세 데이터 구조는 아직 확정하지 않았다.

## 2026-10-19 확정 전제 및 혼동 정정

### 실제 세금 전 수입 자료 조사 — 애드센스 거래 내역

- 정정: 지급액 화면만 보고 세전 자료 확보가 어렵다고 반복 설명하기 전에 기존 서비스의 내보내기 기능을 조사했어야 한다. 사용자는 여러 자료를 추가 작성·업로드하도록 요구받는 방향을 원하지 않는다. 실제 존재하는 자료를 기준으로 입력 형식을 검토한다.
- Google 공식 '애드센스 지급 내역 보기'는 YouTube용 애드센스도 포함한다. 지급 → 지급 정보 → YouTube 결제 계정 선택 → 거래 보기에서 수입·지급·조정·세금을 거래 유형별로 확인할 수 있고 원하는 기간을 지정할 수 있다.
- 같은 거래 내역을 CSV로 다운로드하거나 인쇄할 수 있다. 따라서 송금액 한 줄뿐 아니라 수입과 세금 거래를 함께 확인하는 실제 자료가 존재한다. 월별 수입 항목·관련 조정·세금 항목을 대조해 공제 전 확정 수입과 지급 흐름을 파악할 후보 자료다. 실제 CSV의 컬럼·행 문구·환불·잔액 이월은 아직 확인하지 않아 파서 명세는 확정하지 않는다.
- '수입'과 '지급'을 각각 새 수입으로 더하지 않는다. 이는 수익 발생과 그 잔액의 송금을 나타낼 수 있다. 단순히 지급액+세금으로 모든 기간의 총수입을 확정하지 않고 이월·조정·지급기간을 대조한다.
- [Google 지급 내역 보기·다운로드](https://support.google.com/adsense/answer/12496700?hl=ko), [YouTube 수익 확인](https://support.google.com/youtube/answer/9314488?hl=ko). 2026-10-19 본문 열람. 실제 계정 로그인·CSV 다운로드는 하지 않았다. 단일 파일 전체 서비스 입력 여부·CSV 지원·기존 PDF 담당 연계는 미확정이며 파일 추가 업로드를 요구하는 결정은 하지 않는다.

### 면세와 굿즈 판매 구분

- 면세 1인 창작자라는 등록 상태가 모든 판매를 면세로 만드는 것은 아니다. 면세는 해당 콘텐츠 용역 등 거래의 성격에 적용된다.
- 티셔츠·머그컵·키링 등 일반 굿즈를 직접 판매하는 활동은 원칙적으로 부가세 과세 대상이다. 콘텐츠 용역 면세와 별도로 업종 추가·과세/면세 겸영 등의 검토가 필요하다. 개별 품목의 법정 면세 여부는 별개다.
- 기존 수입 카테고리의 제휴·판매 후보를 유지하더라도 굿즈 판매를 1차 면세 전용 계산에 자동 포함하지 않는다. 실제 판매자인지 제휴 수수료 수령인지도 구분해야 한다. 지원 범위 변경은 사용자 결정 전 미확정이다.
- 근거: [국세청 부가가치세 개요](https://d.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7693&mi=2401), [판매 업종 과세·면세 확인 안내](https://ems.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7804&mi=2483). 2026-10-19 확인.

### 완성된 연간 데이터로 계산하는 설명용 사례

- 미래 예측을 제외하고 장부 기준 계산을 먼저 설명한다. 국세청 세율표의 명시 범위에 맞춰 2025년 귀속 예시로 설명하며 2026년 전체 규칙을 확정한 사례가 아니다.
- 가상 사례: 유튜버 사업소득만 있는 거주자, 검수된 연간 총수입금액 5,000만 원, 해당 연도 필요경비 2,000만 원, 본인 기본공제 150만 원만 반영한다. 다른 소득·공제·감면·결손금은 설명에서 생략한다. 원본 출금 2,000만 원이 자동으로 필요경비 2,000만 원이라는 뜻이 아니다. 원본 입금과 세전 총수입도 같다고 확정하지 않는다.
- 사업소득금액 3,000만 원 → 과세표준 2,850만 원 → 산출세액 2,850만 원 × 15% − 126만 원 = 301만 5천 원. 같은 계산은 1,400만 원 × 6% + 1,450만 원 × 15%다. 15%를 전체 금액에 곱하기만 하지 않는다.
- 301만 5천 원은 이 단순 사례의 산출세액이다. 적용할 세액공제·감면을 확인한 뒤 연간 세액을 정해야 하므로 실제 사용자 최종세액이라고 부르지 않는다. 표준세액공제 등도 지원 범위 확정 시 검토한다. 기납부 차감·추가 납부/환급·지방소득세는 이 예시에서 제외한다.
- 계산 단계: 원본 거래 검수·연간 집계 → 세무상 수입·필요경비 연결 → 사업소득금액 → 소득공제 → 과세표준 → 누진세율 → 산출세액 → 적용 가능한 세액공제·감면 → 연간 예상 종합소득세.
- [국세청 세율표](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7667&mi=2224), [계산 흐름](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7666&mi=2224), [소득세법 제50조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029623963). 2026-10-19 확인. 수입·경비는 예시값이며 개인 조건과 생략 항목을 명시했다.

### 결과·시뮬레이션 화면 구성 — 최신 사용자 확정

- 기본 결과 조회는 비로그인도 가능하다. 시뮬레이션 진입·계산·비교·저장은 로그인 사용자에게만 허용한다. 이전 화면의 비로그인 계산·비교 허용 문구는 수정 대상이다.
- 결과 화면 구성: 연간 예상 종합소득세, 총수입·총지출, 총액 비교·월별 및 카테고리별 시각화, 실제/예상 구간 표시, 산출 근거, 미등록자 사업자등록 안내, 절세 팁, 결과 저장 버튼.
- 결과 저장은 로그인 사용자에게 제공한다. 비로그인 저장 클릭 시 결과와 저장 의도를 유지하고 회원가입·인증 이후 해당 결과를 저장하는 기존 요구를 유지한다.
- 시뮬레이션 입력은 남은 기간의 확정 예정 수입, 확정 예정 업무 지출, 기부 예정액으로 한다. 노란우산 입력은 제거한다.
- 노란우산→기부 변경은 화면 항목 교체이며 계산식 이름만 바꾸는 작업이 아니다. 기부 유형·자격·한도·사업소득만 있는 경우의 필요경비 처리 등 지원연도 규칙을 검증한 뒤 별도 로직으로 구현한다. 입력액 전부를 세액에서 빼거나 기존 노란우산 소득공제식을 재사용하지 않는다.
- 예정 수입·지출은 평균 예측에 추가로 무조건 더하지 않는다. 같은 거래·기간에 해당하는 예측 부분을 확정 예정액으로 대체하거나 중복 제외하는 규칙이 필요하다. 그 매칭 방식과 월별 입력 구조는 후속 설계 사항이다.
- 비교 결과: 기본/변경 후 연간 예상 종소세, 세액 증감 및 확정 예정액 반영 전후 수입·지출. 추가 납부·환급액은 제외한다.
- 화면의 주요 구성과 접근 권한은 정리되었다. 예측 방식, 세금·기부 계산 명세, 실제 API·저장 연결은 미완료다. 이번에는 문서만 반영하고 화면 코드는 수정하지 않았다.

### 시뮬레이션 화면 검토 — 미확정 제안

- 사용자 제공 화면에는 추가 사업 지출·노란우산 납입·추가 수입이 있다. '계산과 비교는 로그인 없이 가능' 문구는 앞서 확정한 로그인 전용 시뮬레이션과 충돌하므로 구현 시 수정 대상이다. 이번에는 코드 변경하지 않았다.
- 절세는 법정 필요경비·소득공제·세액공제·감면을 요건과 한도에 맞게 반영하는 것이다. 서비스는 적용 가능성을 설명하고 동일 계산기로 조건 변경 결과를 비교한다. 근거 없이 확정 혜택을 추천하지 않는다.
- 1차 시뮬레이션 후보는 추가 수입(증가·감소), 사업 지출 계획 변경, 노란우산 추가 납입이다. 사용자 동의 전 후보이며 기존 납입액·가입 및 공제 자격·남은 한도를 반영해야 한다. 비용을 원본에 기록하는 방식과 올해 세무 반영액은 계속 별도 설계 사항이다.
- 노란우산은 납입액 전부를 세금에서 빼는 제도가 아니라 요건·한도 내 소득공제다. 납입으로 현금 유동성이 줄고 해지·수령 조건도 있으므로 세금 감소액만 이득으로 표시하지 않는다. [노란우산 공식 안내](https://www.8899.or.kr/cmnsCnts/view?menuId=C080301000), 2026-10-19 검색 확인. 구체적 2026년 가입·납입·공제 규칙은 구현 전 대조한다.
- 결과 후보: 기준/변경 연간 예상 종소세, 세액 증감, 추가 입금·출금, 세금 반영 후 현금 차이. 노란우산 납입은 소비 지출과 다르게 본인 적립금임을 구분한다. 금액을 실제 추가 납부·환급액으로 부르지 않는다.
- 기부·연금계좌·창업감면은 추가 검증 후 확장 후보로 둔다. 사업소득만 있는 경우의 일반 기부금 처리를 직장인의 기부금 세액공제와 동일하게 만들지 않는다. [국세청 공제 안내](https://www.nts.go.kr/nts/na/ntt/selectNttInfo.do?bbsId=1028&mi=2201&nttSn=1348133), 2026-10-19 기존 조회 자료 참고. 현행 지원연도 대조는 남아 있다.

### 최신 확정 범위 — 연간 예상 종합소득세·시뮬레이션·절세 팁

- 결과는 기납부세액을 차감하기 전의 연간 예상 종합소득세다. 추가 납부·환급액 계산은 선택 기능으로도 제공하지 않는다.
- 이미 낸 세금 직접 입력, 홈택스·위택스·애드센스 납부자료 조회 후 입력 안내 및 자동 연동·수집은 제외한다. 시연용 기납부세액도 별도로 준비할 필요가 없다.
- 핵심은 동일 계산기로 조건 변경 전후의 연간 예상 종소세를 비교하는 시뮬레이션과 근거 있는 절세 팁이다. 세금 감소액과 추가 지출액을 구분한다.
- 총·월별·카테고리별 수입지출 시각화, 산출 근거, 결과 저장, 로그인 전용 시뮬레이션, 회원가입 후 이어 저장, 미등록자 안내는 유지한다.
- 실제 입출금 원본은 유지한다. 세전 수입·경비·공제와 연결할 계산 규칙은 계속 논의한다. 지방소득세 합산 여부와 외국납부세액공제 지원 여부는 이번 변경으로 확정하지 않는다.
- 아래의 납부·원천징수 조회 및 정산액 관련 내용은 과거 검토 이력 또는 세무 개념 참고이며 현재 요구사항이 아니다. 이 절을 우선한다.

### 납부·원천징수 조회 링크 활용 — 제외한 과거 제안

- 홈택스(https://www.hometax.go.kr/)에서 국세 납부내역 및 본인 지급명세서·원천징수 자료를 확인하도록 안내하고 사용자 직접 입력으로 연결하는 방안을 검토한다. 지방세 납부 확인은 위택스(https://www.wetax.go.kr/)가 별도 경로다. 외국 원천징수는 애드센스 정산 자료 등 별도로 확인한다.
- 링크로 이동해 본인이 확인하는 방식이며 우리 서비스가 로그인 정보나 세금 내역을 자동 취득한다는 의미가 아니다. 현재 메뉴와 연중 제출·조회 가능 범위는 구현 시 재확인한다.
- 중요: 납부일 기준 올해 낸 모든 세금을 합산하지 않는다. 예를 들어 2026년 5월 납부한 2025년 귀속 종소세를 2026년 귀속 기납부액으로 빼지 않는다. 계산 대상 귀속연도와 세목이 맞는 원천징수·중간예납 등의 금액을 사용하고 중복 반영하지 않는다. 미조회·미제출 자료를 0원으로 확정하지 않는다.
- 참고: [국세청 신고·납부 안내](https://b.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=238910&mi=40296), [수원시 위택스 이용안내](https://news.suwon.go.kr/ebook/site/src/viewer/download.php?host=main&no=3&site=20250304_043056). 2026-10-19 검색 확인. 상세 메뉴 직접 로그인 검증은 하지 않았다.

### 종합소득세와 개인지방소득세

- 종합소득세는 연간 종합과세 소득에 대한 국세이며 추가 납부·환급 차액만을 뜻하지 않는다. 기본 연간 예상 세액과 기납부세액 반영 후 정산액을 구분한다. 후자는 정보가 있을 때 산출하는 선택 경로로 검토 중이며 최종 화면 우선순위는 다시 합의한다.
- 면세 창작자의 면세 대상 용역에는 부가세가 면제되지만 종합소득세와 개인지방소득세까지 면제되는 것은 아니다.
- 개인지방소득세는 개인 소득에 대해 지자체에 내는 별도 세금이다. 소득세와 같은 과세표준에 지방세율을 적용하고 공제·감면 등 별도 규칙을 반영한다. 최종 종소세에 무조건 10%를 곱하면 모든 사례에서 정확하다고 설명하지 않는다.
- 결과 표시 후보: 예상 종합소득세 / 예상 개인지방소득세 / 합계. 구현·지원연도별 계산식은 미정이다. [강원특별자치도 지방소득세 안내](https://state.gwd.go.kr/portal/administration/non-taxReceipt/localTaxes/income), [관악구 안내](https://www.gwanak.go.kr/site/gwanak/09/10902020800002016051207.jsp). 2026-10-19 확인.

### 나이·지역 입력 목적 재검토

- 자택 사업장: 집이라는 이유만으로 유튜버 사업자등록이 금지되는 것은 아니다. 실제 활동 장소와 사용 권한·임대차 관계 등을 확인한다. 집 주소로 등록하는 사실만으로 과세/면세 또는 창업감면 여부가 자동 결정되지 않는다.
- 창업감면 지역을 판단할 때 주소만 유리한 곳에 두고 실제 다른 곳에서 일하는 형태를 동일하게 취급하지 않는다. [국세청 공개 심판사례](https://taxlaw.nts.go.kr/pd/USEPDA002P.do?ntstDcmId=200000000000019514)는 실제 업무 장소와 형식적 등록 주소의 차이를 다룬다. [사업자등록 서류 안내](https://www.easylaw.go.kr/CSP/CnpClsMainBtr.laf?ccfNo=2&cciNo=2&cnpClsNo=2&csmSeq=1505&popMenu=ov), 2026-10-19 확인. 개별 주택의 허용 여부·계약 조건까지 확인한 것은 아니다.

- 사용자가 나이·창업지역 입력을 생각한 이유는 청년창업중소기업 세액감면이다. 나이는 현재 나이보다 창업 당시 나이가 중요하고 병역기간 조정 등 요건이 있다. 거주지와 실제 창업 사업장 소재지를 혼동하지 않는다.
- 수도권이면 감면된다는 단순 규칙이 아니다. 창업 시점·수도권 과밀억제권역/그 밖의 지역·대상 업종·실질 창업 여부 등에 따라 판단한다. 2026년 이후 창업의 지역별 규정 변화가 있어 창업일 없이 감면율을 확정하지 않는다.
- 1차 대상인 940306 면세 인적용역과 향후 921505 과세 미디어콘텐츠 창작업의 감면 가능성을 동일하게 취급하지 않는다. 면세 인적용역사업자에 대한 감면 배제 해석을 검토해야 하므로 나이·지역만으로 1차 계산에 창업감면을 자동 적용하지 않는다. 현행 적용과 실제 업종 판단을 확인한 뒤 입력 유지 여부를 결정한다. 과세 전환 자체가 새 창업이라는 뜻도 아니다.
- 참고: [국세청 창업 세액감면 안내](https://t.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=239082&mi=41127), [국세청 업종 판단 회신](https://taxlaw.nts.go.kr/qt/USEQTA002P.do?ntstDcmId=200000000000008603). 2026-10-19 확인. 구체적 감면율과 서비스 적용은 미확정이다.

### 계산 설계 진입 — 원천징수 구분

- 사용자 제공 채널 분석 수익 화면 검토: 화면의 29,733원은 '추정 수익'이며 실제 은행 입금액이나 미국 원천징수 차감 후 금액으로 확정할 수 없다. Google은 YouTube 분석에 원천징수액이 표시되지 않으며 최종 원천징수액은 애드센스 지급 거래 보고서에서 확인한다고 안내한다. 추정 수익·확정 수입·실지급액을 혼동하지 않는다. [Google 공식 원천징수 안내](https://support.google.com/youtube/answer/10391362?hl=ko), [수익 확인 안내](https://support.google.com/youtube/answer/9314488?hl=ko). 2026-10-19 열람. 이 화면을 입력 자료로 채택한다는 결정은 아직 없다.

- YouTube 10% 후속 확인: 한국 조세조약상 거주자가 적정 미국 세금 정보를 제출하고 해당 저작권 사용료 조약 혜택을 적용받는 경우의 10%를 설명할 수 있다. 이는 전체 유튜브 수입이 아닌 적용 대상 미국 시청자 수입 부분에 대한 세율이다. 실제 적용은 애드센스에서 확인한다. [미국 IRS 한미조약](https://www.irs.gov/businesses/international-businesses/korea-tax-treaty-documents), [Google 조세요건](https://support.google.com/youtube/answer/10391362?hl=ko). 2026-10-19 확인.
- 광고 연락·계약 경로에는 브랜드 직접, 광고대행사, MCN·중개 플랫폼 등이 있다. 이번 조사로 어느 경로가 다수인지 통계를 확인한 것은 아니다. 실제 계약·지급자와 수입 성격을 기준으로 세무 처리를 검토한다. 중국 브랜드라도 국내 대행사가 연락했다는 사실만으로 국내 원천징수 거래라고 확정하지 않는다. 첫 시연에 국내 지급자의 원천징수 대상 협찬을 쓰는 방안은 제안이며 미확정이다.

- 500만 원 원천징수 예시 정리: 국세청의 15만 원(3%)은 소득세만이다. 지방소득세 특별징수 1만5천 원(지급액의 0.3%)을 함께 보면 총 16만5천 원(3.3%), 실입금은 483만5천 원이다. [공공기관 원천징수 설명](https://www.goe.go.kr/resource/old/BBSMSTR_000000030215/BBS_202411010956274671.pdf), 2026-10-19 확인.
- YouTube의 적용 세율은 애드센스 지급 정보의 미국 세금 정보에서, 실제 징수액은 지급 거래 내역에서 확인하는 방향이다. 제출 정보·조약 혜택·미국 시청자 수입 등에 따라 달라 전체 유튜브 입금에 고정 미국세율을 붙이지 않는다. [Google 공식 안내](https://support.google.com/youtube/answer/10391362?hl=ko), 2026-10-19 재열람. 실제 로그인 메뉴는 직접 검증하지 않았다.
- 중국 브랜드 광고라는 명칭만으로 중국 원천징수 여부·세율을 결정하지 않는다. 실제 계약·지급자, 용역 수행지, 사용권 대가 여부 등 소득 성격과 중국 국내법·한중 조세조약을 검토해야 한다. 국내 대행사를 통한 지급과 중국 법인 직접 지급도 동일하다고 가정하지 않는다. [중국 세무당국 개인소득세법](https://www.chinatax.gov.cn/eng/c102962/c102967/c102997/c103004/c5245849/content.html), 2026-10-19 검색 확인. 특정 광고 계약의 과세 여부는 미판정이다. 해외 광고 지원 범위를 확대할지 사용자 결정 전 임의 확정하지 않는다.

- 원천징수는 받는 사람이 원하면 선택하는 방식이 아니다. 법정 원천징수 대상 소득을 원천징수의무자가 지급하는 경우 지급자에게 징수·납부 의무가 있다. 모든 입금이 대상이라는 뜻은 아니다. '실제 징수 여부 확인'은 선택권 안내가 아니라 소득·지급자 요건과 실제 자료를 확인한다는 의미다. [국세청 간이지급명세서 안내](https://d.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=238925&mi=40349), 2026-10-19 확인. 원천징수 미이행만으로 수입의 납세 의무가 없어지는 것도 아니다.

- 미국 원천징수와 한국 종합소득세는 다른 국가의 과세다. 한국 거주자의 해당 국외소득도 국내 신고에 반영될 수 있어 미국에서 원천징수됐다고 한국 신고가 끝나는 것은 아니다. 이중과세 조정을 위해 외국납부세액공제가 있으며 요건·한도 및 관련 명세 제출이 필요하다. 미국 납부액 전액이 언제나 국내 세금에서 차감되거나 환급된다고 설명하지 않는다. [국세청 외국납부세액공제 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7802&mi=2480), 2026-10-19 재확인. 페이지의 2023년 예시 수치는 현재 계산값으로 채택하지 않는다.

- 모든 수입에 기본 3.3%를 적용하지 않는다. 국내 원천징수 대상 사업소득에 대한 소득세 3%와 지방소득세 0.3%는 최종 종소세율이 아닌 선납 성격이다. 개별 지급의 원천징수 대상 여부와 실제 징수액을 확인한다.
- 유튜브 애드센스 정산에서 Google이 적용할 수 있는 미국 세금 원천징수는 한국의 3.3%와 다르다. 미국 시청자 관련 수입과 제출 세금 정보 등에 따라 달라질 수 있으므로 정산 전체에 국내 3.3%를 일괄 적용하지 않는다.
- 실제 입금액 원본은 유지하되 세금 계산을 위해 정산서의 공제 전 금액·국내 소득세 원천징수·지방소득세·외국 원천징수액 등을 어떻게 확보할지는 추가 설계가 필요하다. 입금액만으로 세전 수입과 선납세금을 항상 복원할 수 있다고 가정하지 않는다.
- 국내 소득세 기납부액과 지방소득세, 외국납부세액을 한 금액으로 합산해 종소세에서 빼지 않는다. 외국납부세액은 해당 요건·한도에 따른 별도 공제 검토 대상이다.
- 근거: [국세청 원천징수](https://j.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7902&mi=6622), [YouTube 수입 안내](https://support.google.com/youtube/answer/72902?hl=ko), [국세청 크리에이터 세무 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7802&mi=2480). 2026-10-19 확인. 개별 적용 세율·대상·공제 규칙 확정은 남아 있다.

### FastAPI 및 Elasticsearch 활용 조사 — 제안·미확정

- 사용자 결정: Elasticsearch를 결과 화면의 상황별 세무 안내·팁 문서 검색에 사용하는 안을 후보로 등록한다. 미등록 여부·지출 카테고리·시뮬레이션 항목 등을 검색 조건으로 활용하고 대상·적용연도를 필터링하는 방향이다. 최종 도입은 미확정이며 공제·세액 판정은 검색 엔진 역할이 아니다.
- 사업자 상태 수집 방식은 아직 결정하지 않았다. 등록 필요성 안내와 등록 상태 사실 수집은 구분한다. 입력에서 미등록 / 등록(면세) / 등록(과세) / 모름을 사용자 선택으로 받는 안은 현재 제안이며 자동 조회·데이터 추론·구현을 확정하지 않는다.

- 사용자가 제공한 React·Spring Boot·FastAPI 연결 강의 자료를 읽었다. 자료의 주식 거래량 예측·DB·명령은 예제이며 현재 프로젝트의 구현 지시나 기존 구현 증거가 아니다.
- FastAPI는 Python API 서버 프레임워크이며 ML 모델 자체가 아니다. 우리 프로젝트에서는 Python 전처리·학습한 분류 모델의 추론을 HTTP API로 제공하는 역할이 자연스럽다.
- 연결 제안: React → Spring Boot(인증·거래 조회·저장·응답) → FastAPI(학습 때와 같은 전처리·모델 추론) → Spring Boot → React. 학습은 별도 스크립트로 하고 서버는 저장된 전처리+모델을 불러 사용한다. 요청마다 다시 학습하지 않는다.
- 미래 금액 예측도 Python 모델을 선택하면 FastAPI에서 제공할 수 있다. 단순 평균·일정 계산으로 충분하면 Spring에서 처리할 수 있으며 FastAPI를 쓰기 위해 ML을 억지로 추가하지 않는다. 세금 계산도 FastAPI 필수 기능이 아니다.
- 강의의 joblib 모델을 Java가 직접 불러오기 어렵다는 설명은 해당 저장 방식에 대한 설명이다. 모델을 웹에서 제공하는 방법이 FastAPI 하나뿐이거나 모든 ML을 Python에서만 실행할 수 있다는 뜻으로 일반화하지 않는다.
- Elasticsearch 후보: 세무 안내·등록 안내·검수한 팁·FAQ의 제목/본문 검색 및 연도·주제 필터. 결과 화면에서 관련 안내를 연결할 수도 있다. 원본 콘텐츠와 출처·적용연도·확인일을 관리하고 검색용 사본을 갱신한다. 검색은 세금 판정이나 답변 생성과 다르다.
- 안내 문서 수와 검색 요구가 적으면 MySQL로도 충분할 수 있다. 거래 합계·차트나 몇 개 고정 팁 표시만을 위해 Elasticsearch를 도입할 필요는 없다. 개인 거래 검색은 사용자별 권한·동기화 부담을 고려해 별도 후보로 남긴다.
- 참고: [FastAPI 기능](https://fastapi.tiangolo.com/features/), [Elasticsearch 검색·필터](https://www.elastic.co/docs/reference/query-languages/query-dsl/full-text-filter-tutorial). 2026-10-19 공식 검색 확인. 모델 서버의 현재 구현·연결 여부는 이번 조사에서 확인하지 않았다. 최종 도입 결정은 미정이다.

### 결과 화면 중심 요구사항 — 사용자 제안 반영

- 상단에 연간 예상 종합소득세를 표시한다. 추가 납부·환급액 및 기납부세액 입력은 최신 사용자 결정으로 제외한다.
- 총수입·총지출, 전체 수입·지출 비교, 월별 수입·지출 추이, 앞서 논의한 수입 출처·지출 용도별 시각화를 구성한다. 관측 기준일·대상 귀속연도와 실제/예측 구간을 구분한다.
- 로그인 사용자는 결과를 저장할 수 있다. 비로그인 사용자가 저장을 누르면 결과와 저장 의도를 임시 보존하고 회원가입·인증 후 같은 결과를 저장하는 흐름을 요구한다. 인증 완료를 확인한 뒤 중복 저장을 방지한다. 서버 저장·개인정보 보관 방식과 API는 구현 시 확인한다.
- 시뮬레이션은 로그인 사용자에게만 허용한다. 화면 접근 제한뿐 아니라 실제 API가 있다면 서버 권한 검사도 필요하다.
- 산출 근거에는 실제·예상 수입, 원본 지출과 계산에 반영한 경비의 관계, 적용 공제·세율·연간 최종 세액·기납부 반영액·차액 및 미반영 조건을 설명하는 방향이다. 세부 세무 계산 규칙은 아직 미정이다.
- 미등록 사용자에게 사업자등록 필요성·면세 유형 안내를 제공한다. 등록 여부로 세금이 자동 절감되는 비교는 하지 않는다.
- 지출 계획·수입 변화·기부 조건을 바꾸는 시뮬레이션과 근거 있는 팁을 제공하려 한다. 구체적 지원 항목은 검증 후 확정한다.
- '먹방이면 식비를 아낄 수 있다'는 검증된 세무 규칙이 아니라 사용자의 활용 예시다. 실제 식비 지출 감소, 필요경비 반영, 세금 감소는 구분한다. 콘텐츠에 등장했다는 이유만으로 모든 식비를 자동 인정하지 않는다.
- 기부도 금액 전액만큼 세금이 줄어든다고 표시하지 않는다. 적격 유형·소득 조건·적용 방식·한도 확인이 필요하다. 수입이 세율 구간을 넘을 때 전체 소득에 새 최고세율을 일괄 적용한다고 설명하지 않는다.
- 현재는 화면을 보며 요구사항을 구체화하는 논의로 기록했다. 결과 화면·회원가입·저장·시뮬레이션 코드 구현은 이번 기록 작업에서 하지 않았다.

### 1차 지원 범위 — 최신 사용자 결정

- 사용자 동의 방향: 계산은 면세 1인 창작자를 중심으로 하고, 취미에서 수익 활동으로 넘어가는 입문자에게 등록·신고 안내를 제공한다. 등록 여부를 자유로운 절세 스위치로 비교하지 않고 등록 후 달라지는 의무·관리 사항으로 설명한다.
- 취미·소액 수입 관련: 본인이 취미라고 부르거나 금액이 작다는 이유만으로 등록 면제를 확정하지 않는다. 국세청은 계속·반복적인 콘텐츠 제작과 수익 발생을 기준으로 등록을 안내한다. 확인한 안내에서 유튜버 공통의 '월 얼마 이하 등록 불필요' 기준은 확인하지 못했다. 일시적 활동은 사업소득과 다른 소득 구분 검토가 필요하며, 이를 이유로 무조건 비과세라고 설명하지 않는다. [국세청 크리에이터 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7802&mi=2480), 2026-10-19 확인. 개별 사례의 등록·소득 구분 판정은 미확정이다.

- 목표 변경: 추가 납부·환급 중심의 이전 목표는 철회했다. 연간 예상 종합소득세와 시뮬레이션·절세 팁을 중심으로 한다.
- 사업자등록과 소득세 의무는 별개다. 등록하지 않았다고 사업소득에 대한 종합소득세 계산·신고 의무가 없어지는 것은 아니다. 계속·반복적으로 수익을 얻는 유튜버의 등록 의무도 따로 검토한다. 미등록 상태와 면세사업자 등록 상태를 같은 것으로 취급하지 않는다. [국세청 사업소득 안내](https://b.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7901&mi=6465), [크리에이터 등록 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7802&mi=2480). 2026-10-19 확인.

- 먼저 면세사업자인 1인 미디어 콘텐츠 창작자(940306)를 대상으로 설계·검증한다. 일상적 의미의 1인 운영만으로 면세를 자동 판정하는 것은 아니며 인적·물적시설 등 요건은 별도 확인한다.
- 과세 유형인 미디어콘텐츠 창작업(921505)은 시간이 남으면 확장한다. 현재 1차 지원 완료 범위로 간주하지 않는다.
- 더미데이터의 기존 카테고리 구분은 그대로 유지한다. 외주비 등 확장과 관련될 수 있는 카테고리를 삭제하지 않는다. 카테고리를 유지하는 것과 해당 거래의 면세 적합성을 확정하는 것은 다르다.
- 현재 설명·시연·계산 검증은 면세 1인 창작자부터 진행한다. 확장용 사례는 1차 검증 사례와 구분하며 검토 없이 면세 사용자 데이터에 섞지 않는다.
- 종합소득세는 해당 귀속연도 1~12월 소득을 다음 해 원칙적으로 5월에 신고·정산하는 구조임을 사용자가 확인했다. 구체적 신고기한 예외 및 세법상 귀속과 실제 입출금의 차이는 기존 확인 사항을 따른다.

### 실제 입출금 원본 — 사용자 확정

- 대상은 1인 유튜버다. 더미데이터는 해당 연도 시작부터 특정 기준일까지 실제로 들어오고 나간 업무 관련 돈을 기록한다.
- 일시불로 300만 원이 나갔다면 지출 300만 원, 할부로 이번 달 30만 원이 나갔다면 이번 달 지출 30만 원을 기록한다. 숫자는 설명용 예시값이다.
- 원본 금액을 전체 구매액으로 환산하거나 감가상각비로 대체하지 않는다. 지출 합계와 미래 입출금 예측은 실제 입출금 기준이다.
- 장비는 이미 업무에 사용한 것으로 전제한다. 사용 여부·사용 시작일·이전 연도 장부 등록 여부를 반복 질문하는 설계는 채택하지 않는다.
- 과거 구매의 할부금이라도 올해 실제 나갔다면 올해 출금 기록에 포함한다.

### 어시스턴트가 잘못 기록한 내용의 철회

- '표시 금액은 전체 구매액으로 통일'은 오해였으며 철회한다.
- '올해 반영할 기존 감가상각비도 더미데이터에 넣는다'는 사용자가 한 말이 아니다. 비현금 조정 행을 따로 작성하도록 요구하지 않는다.
- '올해 신규 구매 장비만 지원'은 확정하지 않았으며 현재 입력 범위의 기준이 아니다.
- 기존 자산 이력·감가상각비 추가 입력과 원본 금액을 인정액으로 변경하는 흐름은 확정 구현안이 아니다.

### 세금 계산과의 연결 — 미정

- 실제 입출금 집계와 세법상 필요경비 산정은 별개다. 입력 전제가 정해졌다고 세무 계산 방식까지 확정된 것은 아니다.
- 현금 지출을 경비로 간주하는 단순 추정으로 갈지, 별도 세무 조정을 계산할지는 후속 논의 사항이다. 어느 쪽도 확정했다고 기록하지 않는다.
- 원본은 유지한다. 세무상 차이를 이유로 실제 출금 기록을 임의 감액·삭제하지 않는다. 경고 문구만으로 현금 지출 전부가 법정 필요경비가 되는 것도 아니다.
- 감가상각·즉시 비용 처리 설명은 세무 개념 참고이며 현재 서비스의 필수 입력·질문 요구사항이 아니다.

### 담당과 진행

- 예측 전 처리 논의: 일회성 거래, 종료일이 있는 할부, 반복 구독, 변동 거래를 구분한 뒤 예상액을 산출하는 방향을 검토한다. 장비 카테고리 자체가 일회성이라는 뜻은 아니다. 할부는 남은 회차·종료일, 구독은 계속 이용 여부 등 알려진 일정이 있다면 평균으로 중복 예측하지 않는다. 필요한 메타데이터와 확인 방식은 미정이다.
- 종소세 기간 설명: 2026년 1~12월 귀속 소득을 원칙적으로 2027년 5월에 신고한다. 신고 월과 소득 합산 기간은 다르다. 입출금 예측과 세법상 귀속 판정도 구분한다. [국세청 신고 안내](https://b.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7664&mi=2224), 2026-10-19 열람.
- 사용자는 외주비가 면세 1인 창작자 범위와 충돌할 수 있다고 지적했다. 국세청은 인적·물적시설에 따라 940306(면세)과 921505(과세)를 구분하고 편집자 고용 등을 예로 든다. 부가가치세법 시행령 제42조에는 고용 외 형태로 주된 업무의 노무 등을 제공받는 경우도 포함하는 문구가 있어 '프리랜서 외주면 무조건 면세 유지'라고 단정하지 않는다. 반대로 외주 지출 명칭 한 건만으로 과세 전환을 자동 판정하지 않는다. 실제 업무 제공 형태와 시설에 대한 검토가 필요하다. [국세청 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7802&mi=2480), [시행령 제42조](https://www.law.go.kr/법령/부가가치세법시행령/제42조). 2026-10-19 확인. 외주 카테고리와 지원할 과세 유형은 미확정이며 사용자 동의 없이 제거·확정하지 않는다.

- 분류 모델 선정 방식 확정: 더미데이터 준비 후 동일 전처리·학습/검증/시험 분할로 LogisticRegression과 LinearSVC를 구현·비교하고 선정한다. 현재 한 모델로 확정하지 않는다. 미분류 기준은 검증 자료로 조정하고 시험 자료로 최종 확인한다. 카테고리별 성능, 자동 분류 정확도와 자동 분류 비율을 함께 비교한다. 생성 틀 중복을 방지한다. 분류 설계 논의는 이 방향으로 일단 마무리한다.
- 다음 논의: 다음 달 및 해당 귀속연도 말까지의 미래 입출금 예측을 평균 기반 메서드로 처리할지 ML로 처리할지 검토한다. 아직 선택하지 않았다. 다음 해 종소세 신고일까지의 입출금을 전년도 귀속연도 예상치에 자동 합산하지 않는다. 신고일과 예측 대상 과세기간은 구분한다.

- 카테고리 모델 조사(2026-10-19): 첫 실험 후보는 사용처·설명을 결합한 텍스트의 문자 n-gram TF-IDF + LogisticRegression, 비교 후보는 동일 특징의 LinearSVC다. TF-IDF는 숫자 특징을 만드는 전처리이며 학습 분류기는 별도다. 선택은 추천 단계이고 최종 확정·성능 측정·구현은 하지 않았다.
- 문자 n-gram은 한국어 띄어쓰기 변형·붙여 쓴 거래 표현을 다루기 위한 실험 후보다. 단어 특징과 비교하며 우수성을 미리 단정하지 않는다. 모델 입력에서 거래·사용자 ID와 정답은 제외한다.
- 미분류는 필수 학습 클래스라기보다 정보 부족·낮은 점수·판단 보류의 서비스 상태로 다루는 방향을 검토한다. LogisticRegression의 predict_proba는 정답 보증이 아니며, 검증 자료에서 임계값과 오분류·자동 분류 비율을 함께 정한다. 알려지지 않은 거래에서 높은 확률로 오분류할 수 있다. LinearSVC는 기본 predict_proba가 없고 결정 점수 또는 별도 보정이 필요하다.
- 후보 비교 기준: 키워드 규칙 대비 macro F1·분류별 F1·혼동표, 미분류 처리 후 자동 분류된 건의 정확도와 자동 분류 비율. 같은 생성 틀·가맹점의 중복으로 평가가 쉬워지지 않도록 분리한다.
- 수입·지출은 카테고리 체계가 달라 별도 분류기 후보로 본다. 수입은 출처 규칙으로 충분한지 먼저 비교하고 ML 추가를 자동 확정하지 않는다. 딥러닝 고도화는 기준 모델 오류와 데이터 확보 후 재검토한다.
- 공식 모델 참고: [TF-IDF](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html), [LogisticRegression](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html), [LinearSVC](https://scikit-learn.org/stable/modules/generated/sklearn.svm.LinearSVC.html). 2026-10-19 열람. 구현 시 설치 버전 대조.

- 최신 사용자 결정: 장비·기기와 소프트웨어·라이선스 카테고리를 구분한다. 장비 구매 지출과 구독 등 반복 지출을 비교하는 데 의미가 있다. 다만 모든 하드웨어가 일시불·단발이고 모든 소프트웨어가 구독이라는 규칙은 아니다. 결제 주기와 카테고리는 별개다.
- 미분류 처리 확정: 자동 분류 후 미분류 거래를 사용자에게 한 번 보여주고 직접 카테고리를 선택할 수 있게 한다. 확인을 건너뛰거나 분류하지 않으면 미분류로 유지한다. 완료를 강제하지 않고 합계·차트에도 포함한다.
- 외부 후원 카테고리는 사용자 의견에 따라 제거한다. 앞서 남긴 외부 후원 후보는 철회한다. 업무 통신비는 확정 거래 없이 확장했던 항목으로 현재 초안에서 제외한다. 나머지 세부 카테고리는 실제 넣을 거래를 보고 검토한다.

- 수입 분류 정정: 유튜브 내 Super Chat·Super Stickers·Super Thanks 및 멤버십은 유튜브 정산 경로에 속한다. 입출금 기준으로 '유튜브 플랫폼 정산'에 포함하고 별도 직접 후원으로 중복 집계하지 않는다. '직접 후원' 후보는 플랫폼 밖 계좌 후원 등 별도 입금만 의미하며 '외부 후원'으로 표현한다. [YouTube 수익 안내](https://support.google.com/youtube/answer/72902?hl=en), 2026-10-19 공식 검색 결과 확인. 세부 수익 구성은 입금 한 건만으로 분해하지 않는다.

- 후속 활용 방향: 지출 분류 결과로 업무 지출의 카테고리별 금액·비중·기간별 변화를 시각화한다. 세금 계산을 위해 분류 ML이 반드시 필요한 것으로 설명하지 않는다.
- 지출의 기타(내용은 알지만 기존 카테고리 밖)와 미분류(정보 부족·모델 불확실)는 구분하는 제안이다. 미분류도 전체 출금 합계에 포함하고 사용자 수정은 선택 사항으로 두는 방향이다. 상세 분류 기준·임계값은 미정이다.
- 사용자 제안: 수입도 출처별 금액·비중·추이를 시각화해 광고·협찬과 유튜브 플랫폼 정산 중 어디에서 수입이 많이 발생하는지 확인하게 한다. 비용 차감 후 이익이 아니라 현재 원본의 실제 입금 기준 수입 분석이다.
- 수입 카테고리 후보는 유튜브 플랫폼 정산 / 광고·협찬 / 기타 / 미분류다. 이는 초안이며 광고·협찬과 플랫폼 광고 수입이 이름상 혼동되지 않도록 설명한다. 플랫폼 정산에 포함된 멤버십 등을 다시 별도 합산하지 않는다.
- 수입 분류 구현은 사용자 선택·확인 가능한 거래 상대 규칙·ML 중 별도로 결정한다. 시각화 제안만으로 수입 분류 ML 추가를 확정하지 않는다. 원본 입금 내역에 구분 정보가 없으면 세부 수입원을 임의 추정해 확정하지 않는다.

- 후속 형식 논의: PDF에는 거래 정보만 표시하고 transactionId는 거래 저장 시 시스템이 생성한다. creatorId는 로그인한 업로드 사용자와 연결한다. 같은 파일 재업로드 중복 검사는 ID 생성과 별개로 처리한다.
- 동일 거래를 PDF 원본 → 시스템 보관 데이터 → 목적별 모델 입력으로 변환한다. 지출 분류 모델 입력의 초안은 사용처·설명이며 정답 카테고리는 학습·평가용으로만 분리한다. 미래 예측은 날짜·금액의 시계열을 별도로 사용한다.
- 사용자 문제 제기: 용도 카테고리마다 고정 인정률이 있는 것이 아니라면 분류 ML이 꼭 필요한지 재검토한다. 분류 ML 도입은 아직 확정하지 않는다. 더미데이터 구성 방향에 동의했다고 ML의 제품상 필요성까지 확정된 것은 아니다.
- 필요경비는 유튜버 전용 고정 품목 목록만으로 판정한다고 가정하지 않는다. 사업 관련성과 해당 비용의 성격·규칙을 확인하는 문제다. 용도 분류와 세무상 인정액을 동일시하지 않는다.
- 카테고리의 활용 후보는 지출 통계, 사용자 검토, 예측 보조 정보다. 합계 중심 계산·예측만으로 요구사항을 충족한다면 분류 ML은 생략 또는 후순위 후보가 된다. 이 활용안은 미확정이다.

- 사용자 동의 방향: 카드·현금영수증 형태 내역 및 현금 거래 수기 입력을 표현하는 더미데이터를 구성한다. 원본에는 카테고리를 미리 확정해 노출하지 않고, 학습·평가용 정답은 분리한다. 실제 입출금 기준은 유지한다.

- PDF 입력·추출은 다른 팀원 담당이다. 사용자는 ML 두 기능, 계산 로직, 시뮬레이션, 세무 정보와 Elasticsearch를 담당한다.
- 티켓 및 Epic 작성·회의는 완료했다. 현재는 계산 구조를 이해하며 방향을 정하는 단계다.
- 아래 기존 구현 제안과 세무 처리 표는 확정 명세가 아니다. 최신 입력 전제와 충돌하면 이 절을 우선한다.

## 프로젝트 구현 정리안: 데이터·계산식·ML

이 절은 이전 논의의 제안이다. 실제 입출금 원본 기준을 우선한다. 아래 세무 조정·직접 입력·계산식은 미확정 검토 후보이며 구현 요구사항이 아니다.

### A. 입력과 결과의 흐름

```text
업무용 수입·지출 PDF + 계산에 필요한 기본 정보·공제 정보(세부 항목 미정)
→ 텍스트 추출 / 필요한 페이지 OCR
→ 거래일·사용처·내용·금액 추출
→ 사용자가 누락·중복·잘못 읽힌 값 확인
→ ML 카테고리 추천 및 사용자 수정
→ 실제 입출금 원본 유지 및 집계
→ 남은 기간 예정액과 미확정 부분 예측
→ 별도 합의할 세금 계산 방식 적용
→ 추가 광고비·지출·기부 등의 시나리오 재계산·비교
```

### B. 필요한 데이터

| 목적 | 필요한 자료·항목 | 확보 방향 |
| --- | --- | --- |
| PDF 추출 | 거래일, 사용처·지급처, 설명, 금액, 입출금 방향, 페이지·원본 행 | 업무 거래 PDF와 정답 표를 짝으로 마련. TJK-5 OCR 작업 활용 가능 여부 확인 |

| 카테고리 ML 학습 | 실제 추출 결과와 비슷한 사용처·설명 + 사람이 확인한 정답 카테고리 | 한국 유튜버 업무 표현 포함. 선별 자료·합성 자료의 출처와 가정 표시 |

분류용 텍스트 자료와 개인별 시계열 자료는 목적이 다르다. 세금 계산에는 거래 외 개인 조건도 필요하므로 PDF 하나에서 모든 값을 얻는다고 가정하지 않는다.

### C. 계산식

아래는 세법상 장부 방식의 참고 구조이며 서비스 적용은 미확정이다. 실제 입출금 원본이 그대로 세무 장부라고 가정하지 않는다. 단순경비율·기준경비율은 적용 요건과 해당 연도 수치를 확인한 뒤 별도 경로로 추가한다.

```text
연간 예상 총수입 = 현재까지 해당 연도 귀속 수입
                  + 남은 기간 반영할 확정 예정 수입
                  + 그 외 부분의 추정 수입

연간 예상 필요경비 = 이미 발생한 지출 중 올해 인정할 경비
                    + 미래 지출 중 올해 인정할 예상 경비

예상 사업소득금액 = 연간 예상 총수입 − 연간 예상 필요경비

예상 종합소득금액 = 사업소득과 다른 종합과세 대상 소득 등을 반영한 금액
예상 과세표준 = 소득공제 등을 반영한 금액(기본 계산은 0 미만이 되지 않게 처리)
예상 산출세액 = 과세표준 × 해당 연도 구간별 세율 − 누진공제
예상 결정세액 = 적용 가능한 세액공제·감면을 법정 순서·한도로 반영한 금액
서비스 결과 = 연간 예상 종합소득세(기납부세액 차감 전). 추가 납부·환급액은 계산하지 않음
```

- 기본 흐름의 공식 근거는 [국세청 계산 흐름](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7666&mi=2224)과 [크리에이터 세무 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7802&mi=2480)다. 아래 출처 표의 적용연도·최신성 상태를 함께 확인한다.
- 확정 예정액이 포함된 기간·항목을 평균 예측으로 다시 더하지 않는다. 예측 수입의 발생과 세법상 귀속 판단을 구분한다.
- 필요경비는 전체 결제액이 아니다. 자산·혼용 지출·부가세 처리 등을 거쳐 산정한다.
- 공제·감면은 고정 일괄 차감이 아니다. 개인 조건·소득 종류·한도·이월 규칙을 확인한다. 기부는 거래 분류와 별도로 적격 유형·처리를 확인한다.
- 위 식은 기본 구조이며 결손금 등 예외를 모두 구현한 계산 명세가 아니다. 지원 범위를 벗어난 입력은 정확한 계산을 지원한다고 표시하지 않는다.
- 지방소득세·부가가치세는 별도 계산 경로로 관리한다. 외국 납부세액은 국내 기납부세액에 단순 합산하지 않는다.
- 화면은 연간 예상 종합소득세를 표시하고 추가 납부·환급액은 제공하지 않는다.

### D. ML과 규칙 기반 처리의 역할

| 기능 | 처리 방식 제안 | 입력 → 출력 | 검증 |
| --- | --- | --- | --- |
| PDF 읽기 | 기존 PDFBox·Tess4J 작업 우선 검토 | PDF → 거래 후보 | 정답 표와 날짜·금액·행 누락 대조. 실제 실행 상태는 미확인 |
| 지출 카테고리 추천 | ML 우선 적용 후보. TF-IDF + 로지스틱 회귀 기준 모델 검토 | 사용처·설명 → 교통비·장비비·외주비·구독료 등 | 단순 키워드 규칙과 비교, 분류별 F1·혼동 확인, 모르는 표현 평가 |
| 미래 수입·지출 | 시계열 자료 확보 후 회귀 모델 검토. 우선 최근 평균 기준선 | 과거 금액·날짜·계획 → 미확정 미래 금액 | 시간순 과거 학습·미래 평가, 금액 오차와 최종 세액 오차 측정 |
| 반복 지출 확인 | 처음에는 사용처·금액·주기 규칙 | 거래 이력 → 정기 지출 후보 | 실제 반복·취소 여부 사용자 확인 |
| 세금 계산·경비 처리 | 귀속연도별 세법 규칙 | 검수한 수입·경비·개인 조건 → 세액 | 공식 사례와 경계값 검산 |
| 시나리오 비교 | 동일 계산기를 조건 변경 후 재실행 | 기준값 + 사용자 변경값 → 세액 차이·추가 지출 | 같은 조건이면 같은 결과인지 확인 |

모델 후보는 확정하지 않는다. 공식 참고: [scikit-learn 텍스트 특징 추출](https://scikit-learn.org/stable/modules/feature_extraction.html#text-feature-extraction), [시간순 평가](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html). 2026-10-18 대화 중 열람. 라이브러리 stable 문서는 버전이 바뀔 수 있으므로 구현 때 설치 버전에 맞춘다.

학습·평가에 같은 합성 문장 틀이나 거의 같은 사용처 문구가 섞이지 않도록 분리한다. 학습·추론용 PDF에는 정답 카테고리를 노출하지 않는다. 미래 수익을 평가할 때 예측 시점 이후에 알게 된 실제 조회수·수익을 입력에 넣지 않는다.

### E. 현재 우선순위와 미정 사항

1. 지원할 귀속연도·사용자 조건·공제 항목과 PDF 양식 하나를 정한다.
2. 업무 거래의 분류 목록을 정하고 표본·정답 표·가상 PDF를 검수한다.
3. 기본 종소세 계산을 검산 가능한 규칙으로 구현한다.
4. PDF 추출과 카테고리 ML을 연결하고 오류 수정 흐름을 확인한다.
5. 시계열 자료가 확보되면 미래 예측 모델을 비교한다. 확보 전에는 사용자 예정액과 단순 기준선임을 명시한다.

아직 확보되지 않은 핵심 자료는 한국 유튜버 업무 거래 분류 표본과 동일 사용자의 연속 수입·지출 이력이다. 합성 자료로 개발할 수 있지만 실제 예측 성능까지 입증한 것으로 설명하지 않는다.

## 가장 단순한 계산 흐름

```text
한 해 수입 − 인정 경비 → 사업소득금액
다른 종합과세 대상 소득·공제·세율·세액공제 등을 반영 → 최종 종합소득세
최종 종합소득세 − 이미 낸 소득세 → 추가 납부 또는 환급
```

이것은 이해를 위한 기본 흐름이다. 결손금·가산세 등 세부 항목은 계산 명세에서 추가한다. 개인지방소득세는 별도 정산한다.

연중에는 남은 기간의 수입·경비와 기납부 예상액도 추정해야 한다. 따라서 결과는 확정세액이 아닌 예상세액이며, 미리 낸 세금의 차이와 미래 예측 오차는 구분한다.

## 먼저: 세금과 종합소득세의 차이

**세금은 여러 종류의 세금을 통틀어 부르는 말이고, 종합소득세는 그중 하나다.**

| 말 | 뜻 |
| --- | --- |
| 세금 | 종합소득세, 부가가치세, 지방소득세 등을 포함하는 전체 이름 |
| 종합소득세 | 개인의 한 해 종합과세 대상 소득을 합산하고 공제 등을 반영해 계산하는 소득세 |

크리에이터가 접하는 항목을 구분하면 다음과 같다.

- **종합소득세**: 수입에서 인정 경비를 빼는 등 소득을 계산하고, 다른 종합과세 대상 소득과 공제 등을 반영해 정산한다.
- **부가가치세**: 재화·용역의 공급과 관련된 별도 세금이다. 과세·면세 유형에 따라 의무가 달라진다.
- **개인지방소득세**: 개인의 소득에 대해 지방자치단체에 내는 별도 세금이다.
- **3.3% 원천징수**: 별도의 세금 이름이 아니라, 해당 지급액에서 소득세와 지방소득세를 미리 떼어 납부하는 방식이다. 최종 세금이 확정됐다는 뜻이 아니다.

우리 서비스에서 ‘예상세액’을 표시할 때는 **예상 종합소득세인지, 개인지방소득세까지 포함한 금액인지, 이미 낸 세금을 뺀 추가 납부 예상액인지**를 명확하게 적는다. 부가가치세는 별도로 구분한다.

근거: 아래 공식 출처의 국세청 종합소득세 계산 흐름과 크리에이터 세무 안내를 참고한다.

## 1. 서비스가 하려는 일

- 대상은 1인 유튜버다. 전달받은 화면은 흐름 참고용이며, 화면의 예시 금액이나 계산 방식은 확정 규칙이 아니다.
- 수입·지출을 직접 입력하거나 자료를 업로드한다.
- 연중 어느 시점이든 현재 내역과 남은 기간의 예상치를 바탕으로 연간 예상세액을 계산한다.
- 예정 광고비, 필수지출, 장비 구매, 기부 계획 등을 바꾸고 기준 결과와 비교한다.
- 사업자등록 필요 여부와 유형별 의무를 안내한다. 등록 여부만 바꾸면 종합소득세가 자동으로 줄어든다고 가정하지 않는다.

## 2. 수입·경비·소득

### 경비 인정은 무엇으로 판단하는가

#### 세무 처리 분류 — 과거 제안·미채택

다음은 세무 개념 참고용 과거 제안이며 필수 질문이나 확정 데이터 구조가 아니다. 원본 입출금액은 변경하지 않는다. 세무 처리 후보는 ‘일반 비용 후보 / 자산 구입 후보 / 별도 처리·확인’으로 나눈다. 이는 법정 계정과목이 아니라 계산 누락을 막기 위한 서비스 내부 구분이다.

| 내부 구분 | 예 | 다음 처리 |
| --- | --- | --- |
| 일반 비용 후보 | 촬영 이동 교통비, 편집 외주비, 월 단위 프로그램 이용료 | 증빙·귀속 기간·업무 사용 부분 등을 확인해 비용 반영 |
| 자산 구입 후보 | 카메라, 컴퓨터, 촬영 장비 취득 | 금액·품목·취득일·사용 시작일을 확인하고 감가상각 또는 즉시 비용 처리 예외 검토. 고가인지 여부 하나로 판정하지 않음 |
| 별도 처리·확인 | 임차보증금, 대출 원금 상환, 기부, 불명확한 거래 | 일반 경비 합계에서 분리하고 실제 성격과 해당 규칙 확인. 확인 필요를 자동 불인정으로 취급하지 않음 |

원본에 상세 계정과목이 있으면 그대로 보관한다. 교통비·외주비·구독료·장비비 등의 상세 용도 분류와 위 세무 처리 상태는 별도 필드로 둔다. ML은 상세 용도·처리 후보를 추천할 수 있지만 최종 비용 반영 금액을 임의 결정하지 않는다.

참고: [국세청 간편장부 안내](https://nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7670&mi=2231). 확인일 2026-10-19. 장부·증빙 안내를 확인했으며, 자산별 즉시 비용 처리 조건·금액 한도는 아직 확정하지 않았다.

실제 장부 방식에서 출발점은 ‘사업 수입과 관련하여 통상적으로 발생하는 비용인가’다. 소득세법 제27조는 해당 과세기간의 총수입금액에 대응하는 일반적으로 용인되는 통상적인 비용을 필요경비의 기본으로 정한다.

| 확인 질문 | 예시와 의미 |
| --- | --- |
| 사업과 관련된 지출인가? | 촬영장 이동 택시와 개인 약속 이동 택시는 같은 교통비여도 용도가 다르다. |
| 실제 거래·금액·용도를 설명할 자료가 있는가? | 카드 내역, 영수증, 계약서, 촬영 일정 등으로 확인한다. 증빙의 종류·의무·예외는 별도 검토한다. |
| 전부 업무용인가, 개인용이 섞였는가? | 혼용 통신비 등은 합리적인 업무 사용 부분을 확인한다. |
| 올해 얼마를 비용으로 반영하는가? | 장비 등 자산의 감가상각, 귀속 시기, 한도·불산입 규칙을 검토한다. |

카테고리는 판단에 필요한 정보를 정리하는 도구다. ‘교통비’라는 분류만으로 자동 인정하지 않는다. 반대로 증빙 부족을 모두 자동 불인정으로 처리하는 것도 피한다. 거래 사실·업무 관련성 입증과 법정 증빙 의무 및 가산세 판단은 구분해야 한다.

프로젝트가 업무용 거래만 입력받는다고 전제하면 업무 관련성은 입력 범위에서 확인하고, ML은 용도 분류를 추천한다. 세무 조정 구현 여부와 구체적인 계산 방식은 미정이다.

근거: [소득세법 제27조 조문](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031990913), [국세청 크리에이터 세무 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7802&mi=2480). 확인일 2026-10-19. 제27조 기본 원칙을 확인했으며, 개별 지출별 현행 시행령·한도·자산 처리 예외까지 검증한 것은 아니다.

| 용어 | 뜻 |
| --- | --- |
| 수입 | 비용을 빼기 전, 활동을 통해 얻은 금액. 실제 입금액과는 구분한다. |
| 지출 | 사용자가 쓴 돈 전체. 모두 사업 경비가 되는 것은 아니다. |
| 필요경비 | 세금 계산에서 사업 관련 비용으로 인정되는 금액 |
| 사업소득금액 | 실제 장부 기준으로 총수입금액에서 필요경비를 뺀 금액 |

```text
총수입금액 − 필요경비 = 사업소득금액
```

‘수입’은 순수익이 아니다. ‘사업소득금액’도 일상적인 순수익과 항상 같지는 않다. 개인 지출이나 장비의 자산 처리처럼 세법상 조정이 있기 때문이다.

사업소득에 해당하면 미등록 상태라고 해서 경비를 전혀 반영할 수 없는 것은 아니다. 사업자등록 의무와 소득금액 계산은 구분한다. 실제 경비 반영 여부는 업무 관련성·증빙·적용 계산 방식 등을 확인한다.

## 3. 수입 분류안

아래는 서비스 입력용 분류이며 세법상 소득 구분을 확정한 표가 아니다.

| 분류 | 예 |
| --- | --- |
| 유튜브 광고·프리미엄 | 영상·쇼츠 광고, Premium 배분 수익 |
| 멤버십·후원 | 채널 멤버십, 슈퍼챗, 슈퍼땡스, 외부 플랫폼 후원 |
| 광고·협찬 | 브랜드 광고, PPL 계약 수입 |
| 제휴 수수료 | 제휴 링크 구매·가입 수수료 |
| 기타 사업 수입 | 강의·출연·콘텐츠 판매 등. 세부 내용 확인 필요 |

유튜브 활동 외 월급 등은 별도 소득으로 받는다. 같은 정산액을 여러 수입 분류에 중복 기록하지 않는다.

각 항목에는 현재까지 확인된 내역인지, 계약으로 예정된 금액인지, 단순 예상인지도 구분한다. 이 상태는 예측용 정보이며 세법상 수입 귀속 시점을 대신하지 않는다.

## 4. 3.3% 원천징수

### 핵심

3.3%는 모든 유튜버 수입에 적용하는 최종 세율이 아니다. 해당 원천징수 대상 인적용역 사업소득을 지급할 때 미리 떼는 세금이다.

- 소득세: 지급액의 3%
- 지방소득세: 지급액의 0.3%
- 합계: 지급액의 3.3%

경비를 빼고 남은 이익에 곱하는 것이 아니라 원천징수 대상 지급액을 기준으로 계산한다. 모든 입금에 자동 적용하지 않고 지급명세·정산 자료 등으로 실제 원천징수 여부를 확인한다.

### 이해용 예시값

광고비 1,000,000원에 3.3% 원천징수가 적용되는 경우를 가정한다.

| 항목 | 예시값 |
| --- | ---: |
| 세전 수입 | 1,000,000원 |
| 원천징수 소득세 | 30,000원 |
| 원천징수 지방소득세 | 3,000원 |
| 실제 입금액 | 967,000원 |

추가 수수료·부가가치세 등은 없는 단순 예시다. 이 경우 수입을 입금액 967,000원으로만 기록하면 세전 금액과 구분할 수 없다.

국세와 지방세는 별도로 정산한다. 국내 원천징수 소득세와 외국 납부세액도 같은 항목으로 합치지 않는다.

## 5. 세금 계산에 필요한 큰 묶음

| 묶음 | 내용 |
| --- | --- |
| 기본 정보 | 귀속연도, 사업자등록 여부, 과세 유형, 다른 소득 유무 등 |
| 수입 | 세전 수입, 실제 입금액, 수익 종류 등 |
| 지출 | 사용 금액, 업무 용도, 증빙 등. 필요경비 판단 전 원본 정보 |
| 공제·감면 정보 | 가족, 연금, 기부 등. 적용 자격·한도는 별도 확인 |
| 이미 낸 세금 | 원천징수, 중간예납 등. 세목별 분리 |

예상 계산과 시뮬레이션은 같은 세금 계산 규칙을 사용한다. 미래 수입·지출 예측과 세법 계산은 분리한다.

### 학원 프로젝트의 입력 방식 제안 — 미확정

### 수입·지출 카테고리의 필요성 — 설계 제안

두 내역 모두 서비스용 카테고리를 두는 것을 제안한다. 카테고리 이름 자체가 세금 계산에 반드시 필요한 법정 입력값이라는 뜻은 아니다.

| 대상 | 분류하는 목적 | 시작할 분류 예 |
| --- | --- | --- |
| 수입 | 수입 출처별 확인, 정산 자료 대조, 반복 수입과 비정기 수입의 예측 | 유튜브 정산 / 광고·협찬 / 기타·미분류 |
| 지출 | 용도 확인, 경비·자산 처리 검토, 지출 통계와 반복 지출 예측 | 장비 구입 / 외주비 / 구독료 / 기타·미분류 |

- 세금 계산에는 분류명보다 실제 거래 성격과 계산에 반영할 금액이 중요하다. 분류명만으로 경비 인정·원천징수·부가세 처리를 결정하지 않는다.
- 수입은 출처 분류와 별도로 세전 금액·실입금액·국내 원천징수·외국 납부세액·통화 등을 필요한 범위에서 구분한다.
- 지출은 용도 분류와 별도로 업무 관련성·업무 사용 비율·증빙·자산 처리 등을 검토한다.
- 분류 선택을 몰라 입력을 중단하지 않도록 ‘미분류’를 허용하고 나중에 확인할 수 있게 한다.
- 세법상 소득 구분과 서비스용 수입 카테고리는 별개다. 근거는 공식 출처의 소득금액 계산·원천징수 안내이며, 위 분류 목록은 팀 설계안이다.

### 간단한 입력 방식 — 설계 제안

### 업무 거래만 사용하는 데이터 범위 — 사용자 제안

- 학원 프로젝트에서는 입력 데이터를 ‘유튜브 업무 관련 거래만 모은 내역’으로 한정하는 방안을 사용자가 제안했다. 이 전제를 채택하면 업무용·개인용 판별은 ML 범위에서 제외할 수 있다.
- 지출 분류 ML의 역할은 업무 거래를 교통비·장비비·외주비·구독료 등으로 추천 분류하는 것이다. 택시·버스·지하철 내역을 교통비로 묶는 기능이 해당한다.
- 자체 생성·선별한 시연 데이터에는 이 범위를 명시한다. 출처가 다른 공개 데이터에 업무 거래라는 이름만 붙여 실제 업무 데이터라고 주장하지 않는다. 원본에 업무 용도 정보가 없으면 업무용이라고 가정한 시연 자료임을 표시한다.
- 학습용 데이터에는 거래 설명과 정답 카테고리를 함께 둔다. 원본 거래 설명이 ‘카드 결제’처럼 불명확하면 정확한 분류가 어려울 수 있으므로 사용처·품목 등 이용 가능한 정보를 확인한다.
- 업무 관련성은 데이터 전제로 두더라도 모든 지출을 결제 연도 필요경비로 전액 처리한다고 가정하지 않는다. 장비의 자산 처리·업무 사용 비율·증빙 등 적용 규칙은 세금 계산 단계에서 별도로 확인한다.
- 모델 평가는 이 업무 거래 범위에 한정한다. 실제 개인·업무 혼합 내역에서의 성능을 검증한 것으로 설명하지 않는다.

### 입력 항목 제안

### PDF 입력과 ML 데이터의 구분 — 현재 방향

- 입력 문서 구분 정정(2026-10-19): 사용자는 카드 원본 명세서가 아니라 신고를 위해 업무 거래를 선별·기록한 문서를 염두에 두고 있다. 따라서 개인·업무 혼합 카드 내역을 기본 전제로 설명하지 않는다. 구체적인 문서 양식과 이미 포함된 항목은 아직 미확인이다.
- 업무 거래만 선별한 장부라면 업무 관련성은 입력 전제로 둘 수 있다. 다만 ‘업무 지출을 기록한 문서’와 ‘올해 인정 경비까지 세무 검토된 문서’는 구분한다.
- 이미 지출 계정과목·분류가 있는 장부라면 같은 분류를 다시 예측하는 ML의 필요성은 낮다. 카테고리가 없거나 사용자의 표현을 서비스 표준 분류로 통일해야 하는 경우에만 분류 ML의 가치를 검토한다. 실제 샘플을 본 뒤 모델 적용 여부를 결정한다.

- 사용자는 거래내역을 받는 입력 형식으로 PDF가 적합하다고 판단했다. 카드·은행 중 지원할 명세서 종류와 양식, 스캔 PDF 지원 여부는 아직 정하지 않았다.
- 처리 흐름 제안: PDF 업로드 → 거래일·사용처·설명·금액 추출 → 사용자 확인·수정 → 수입·지출 분류 추천 → 경비 처리 등 세법 규칙 반영 → 예상세액 계산.
- PDF 추출은 문서에서 거래 표를 만드는 단계이고, 분류 ML은 추출한 설명·사용처로 카테고리를 추천하는 단계다. 텍스트 PDF는 텍스트·표 추출을 우선 검토하고, 스캔·이미지 PDF는 OCR이 별도로 필요하다.
- 학습 데이터는 정답 카테고리가 포함된 구조화 자료로 관리할 수 있다. 시연용 PDF를 생성하더라도 정답 원본을 함께 보관해 추출 결과와 대조한다.
- 평가용 PDF나 모델 입력에는 정답 카테고리를 넣지 않는다. 정답을 입력에 노출해 분류 성능이 좋아지는 문제를 방지한다.
- 먼저 한 가지 양식의 텍스트 PDF로 범위를 제한하는 것을 제안한다. 가상 PDF에서의 성공이 실제 카드사·은행 양식 전체의 지원을 의미하지는 않는다.
- OCR 기존 구현 확인(2026-10-18): 로컬에 저장된 원격 추적 브랜치 `origin/feature/TJK-5`에 PDFBox·Tess4J 의존성, 한국어·영어 OCR 설정, `TaxOcrService.extract` 호출이 있다. 단, 해당 참조의 추적 파일에서 `TaxOcrService` 구현은 발견하지 못했으며 `TaxValidator`도 서비스의 참조 패키지와 실제 위치를 대조해야 한다. 실행 가능한 완성 상태는 미확인이다. 현재 `feature/khs`는 스캔 PDF OCR 미지원 메시지가 남아 있다. 브랜치 전환·병합·실행은 하지 않았고 원격 최신 fetch도 하지 않았다. 따라서 OCR은 신규 도입을 전제하기보다 TJK-5 작업의 완성도·필요 파일·실행 환경부터 확인한다.

### 입력 항목 제안 상세

- 실계좌·카드·세금 납부내역의 자동 연동을 필수로 두지 않는다.
- 수입·지출 파일 업로드 또는 직접 입력으로 시작한다. 업무용 카드가 있으면 그 내역을 우선 받고, 계좌 지급·현금 지출 등은 추가 입력한다.
- 지출 카테고리는 장비·외주·구독 등 통계와 분류를 위한 정보다. 카테고리만으로 경비 인정 여부를 확정하지 않는다.
- 이미 낸 소득세 직접 입력과 추가 납부·환급액 계산은 최신 사용자 결정으로 제외했다.

## 6. 사업자등록과 과세 유형

국세청은 계속적·반복적으로 콘텐츠를 생산하고 수익이 발생하면 인적·물적시설 여부에 따라 과세 또는 면세사업자로 등록하도록 안내한다.

- 고용·물적시설이 없는 유형: 1인 미디어 콘텐츠 창작자, 업종코드 940306, 부가가치세 면세.
- 인적 또는 물적시설을 갖춘 유형: 미디어 콘텐츠 창작업, 업종코드 921505, 부가가치세 과세.
- 면세는 부가가치세에 대한 구분이다. 종합소득세까지 면제한다는 뜻이 아니다.
- 수익 없는 취미 활동과 계속적인 수익 활동을 구분하고, 혼자 운영한다는 사실만으로 등록 불필요라고 판단하지 않는다.

### 건강보험 피부양자와의 관계 — 별도 검토

가족 중 보험료를 내는 사람이 있다는 사실만으로 본인의 보험료가 면제되는 것은 아니다. 직장가입자인 가족의 피부양자로 인정될 수 있는 관계·소득·재산 요건을 함께 확인해야 한다.

대화에서 확인한 피부양자 사업소득 요건의 기본 구조는 다음과 같다. 주택임대소득·장애인 등 예외가 있으며, 최신 법령 대조 전 서비스 판정 규칙으로 확정하지 않는다.

| 구분 | 사업소득 요건의 기본 구조 |
| --- | --- |
| 사업자등록 있음 | 원칙적으로 사업소득이 없어야 한다. |
| 사업자등록 없음 | 사업소득금액 연 500만 원 이하를 사업소득이 없는 것으로 보는 예외가 있다. |

위 기준만 충족해도 무조건 피부양자가 되는 것은 아니다. 전체 소득·재산·부양 요건 등이 추가된다. 피부양자 자격을 상실하면 별도 보험료 부담이 생길 수 있으나, 구체적 가입 형태와 보험료는 따로 판단해야 한다.

건강보험료는 세금이 아니다. 사업자등록과 건강보험 부담의 관계는 살펴볼 수 있지만, 피부양자 유지를 위해 등록 의무를 무시해도 된다는 의미로 안내하지 않는다.
