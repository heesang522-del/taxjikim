# 로컬 JWT 서명 키

키는 최초 한 번만 무작위로 생성하고 같은 파일을 계속 읽는다. 서버 재시작 때 새 키를 만들지 않는다.

## 현재 PC

`jwt-secret.properties`가 생성되어 있다. 이 파일은 Git에서 제외되며 키 값은 로그에 출력하지 않는다.

서버 실행 작업 디렉터리를 `taxjikim/back`으로 설정한다. Spring이 `config/jwt-secret.properties`를 읽어 `JWT_SECRET`을 제공한다.

## 다른 PC에서 준비

`back` 폴더에서 다음 스크립트를 한 번 실행한다.

```powershell
.\scripts\Initialize-JwtSecret.ps1
```

이미 키 파일이 있으면 그대로 유지한다. 파일을 삭제하고 다시 생성하면 기존 토큰은 사용할 수 없다.

## 환경변수로 제공

- `JWT_SECRET`: 32바이트 이상의 무작위 키를 Base64로 표현한 값. 로컬 키 파일보다 우선 적용된다.
- `JWT_SECRET_FILE`: 로컬 키 파일의 다른 경로를 지정할 때 사용. 예: `C:/kh_final/taxjikim/back/config/jwt-secret.properties`.

서버를 여러 대 운영하면 같은 인증 체계에서 사용하는 키를 안전하게 공유해야 한다. 각 PC에서 별도로 만든 키는 서로 다르다.

Base64는 저장 표현이며 암호화가 아니다. 키 파일을 공개하거나 Git에 넣지 않는다. 운영 환경에서는 서버 환경변수나 비밀 관리 서비스를 사용한다.

## 최초 전환

이전 코드의 예시 문자열 서명 키를 교체했으므로 이전에 발급된 토큰은 재로그인이 필요하다. 이후에는 같은 키 파일을 유지하면 재시작 후에도 기존 토큰을 검증할 수 있다. 토큰 만료 및 Redis의 로그인 세션 상태는 별도로 적용된다.

## 검증 범위

- 생성 스크립트를 두 번 실행해도 키가 유지됨.
- 키 파일의 Git 제외 확인.
- Spring 설정에서 로컬 파일을 읽는지 확인.
- 새 Spring 컨텍스트에서 기존 Access/Refresh 토큰 검증 확인.
- 다른 키로 기존 토큰을 검증하면 거부됨.

현재 build.gradle에 누락된 인증 관련 의존성은 임시 검증 설정에서만 보충했다. 실제 의존성 추가와 전체 서버 실행 검증은 별도 작업이다.
