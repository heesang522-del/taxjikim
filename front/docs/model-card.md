# 모델 카드

## 로그인·계정 찾기 기본 높이 통일 (2026-11-11)

- 로그인·아이디 찾기·비밀번호 찾기는 기존 공통 Card의 내부 폼에 최소 높이 286px과 세로 배치를 적용하고, 주 버튼의 위 여백을 자동으로 채워 버튼의 상하 위치를 맞춘다. 별도 div나 빈 하단 공간은 추가하지 않는다.
- 회원가입 폼 높이는 유지한다. 오류·인증 안내 또는 좁은 화면에서 내용이 늘어나면 카드가 자연스럽게 확장되도록 최소 높이만 지정한다.

## 관리자 휴면 계정 복구 (2026-11-10)

- 기존 회원 관리 목록에 잠금·이용 정지뿐 아니라 휴면 계정도 표시하고 `휴면 해제`를 제공한다. 기존 관리자 API의 권한 검사와 확인창을 유지한다.
- 휴면 해제 시 ACTIVE로 변경하고 기존 로그인·실패 기록을 초기화한다. 즉시 다시 휴면 처리되지 않도록 기존 휴면 복구 방식과 같이 LAST_LOGIN_AT을 복구 시각으로 갱신한다. 잠금·이용 정지 해제의 LAST_LOGIN_AT은 유지한다.
- 사용자용 별도 휴면 복구 API는 제공하지 않으며 관리자에게 해제를 요청하는 방식이다. 스케줄러 설정은 변경하지 않는다.

## 미사용 인증·회원 코드 정리 (2026-11-10)

- 회원가입·계정 찾기·비밀번호 재설정은 서버 API 경로를 유지하고, 사용하지 않는 mock 인증 메서드·회원 관리 Hook·예시 계정 상태를 제거한다. 접속 표시와 다른 기능의 mock 데이터는 유지한다.
- 프론트에서 호출하지 않는 명시적 토큰 재발급 API와 휴면 복구 API를 제거한다. JWT 필터의 자동 재발급·휴면 자동 전환·관리자 계정 잠금 해제는 유지한다.

## 회원 입력 제약조건 통일 (2026-11-10)

- 회원가입의 아이디는 영문 대소문자·숫자·밑줄만 입력할 수 있고 최대 20자다. 한글·공백·다른 특수문자는 입력 시 차단하고 조합 입력·붙여넣기에서도 제거한다. 중복 확인과 가입에는 최소 4자가 필요하다. 차단된 문자만 입력해 실제 값이 같으면 기존 중복 확인은 유지한다.
- 이메일은 최대 255자, 한글·내부 공백 불허, 이메일 형식 검사를 적용한다. 이메일은 현재 입력값을 유지하고 필드별 오류를 표시한다.
- 프론트의 `userValidation.js`를 회원가입과 마이페이지 이메일 발송·인증·저장에서 재사용한다. 앞뒤 공백 제거 후 검증하며 백엔드에서도 같은 조건으로 검증·저장한다.
- 백엔드는 가입·중복 확인·이메일 인증 발송/확인·마이페이지 이메일 변경에 공통 검증을 적용한다. 기존 로그인·닉네임 규칙과 DB 컬럼 크기는 유지한다.

## 회원가입 이메일 인증 후 잠금 (2026-11-10)

- 이메일 인증 성공 시 인증한 주소를 기록하고 입력칸을 읽기 전용으로 잠근다. 발송 버튼은 비활성화된 `인증 완료`로 표시하며 인증번호 입력 영역은 숨긴다.
- 별도의 `이메일 변경` 버튼에서 브라우저 확인창을 표시한다. 취소하면 유지하고, 확인하면 잠금·인증 완료·인증번호·발송 타이머를 초기화한다. 주소 자체는 유지해 수정할 수 있게 한다.
- 인증 유효시간이 만료돼도 이메일 잠금은 유지한다. `다시 인증받기`로 같은 주소를 재인증하거나 이메일 변경을 선택할 수 있다.
- 인증 전 주소를 변경하면 발송 내역을 초기화하고, 변경 전 주소의 늦은 발송·인증 응답은 무시한다. 유효한 인증은 현재 입력 주소와 인증받은 주소가 일치해야 한다.

## 회원가입 중복 확인 후 값 변경 (2026-11-10)

- 아이디·닉네임은 입력을 잠그지 않는다. 값을 변경하면 확인 성공 상태를 취소하고 중복 확인 필요 안내를 표시한다. 원래 값으로 되돌려도 재확인해야 한다.
- 중복 확인 성공 시 해당 확인 버튼은 비활성화하고, 값을 수정하면 다시 활성화한다. 중복 응답이나 요청 실패 시에는 재확인할 수 있다.
- 다음 단계에서는 아이디 확인 여부, 최종 가입에서는 아이디·닉네임 확인 여부를 검사한다. 다음·가입 버튼이 사용자 확인을 자동으로 대신하지 않는다.
- 아이디·닉네임 입력칸의 Enter는 중복 확인을 실행하며, 성공 후 다음 입력 또는 가입 버튼으로 이동한다.
- 요청 중 입력이 변경되면 이전 응답의 성공·실패 안내와 포커스 이동을 무시한다. 요청 중에는 기존처럼 입력 영역을 비활성화한다.
- 가입 직전 서버 중복 검사와 DB의 최종 중복 방지는 유지한다. 이메일 변경 및 문자·길이 제한 정책은 별도 작업이다.

## 연도별 비교 단위·툴팁 표시 (2026-11-09)

- 비교 표의 금액에 `만원`을 붙이고, 각 그래프 제목 옆에도 단위를 표시한다. 값이 없으면 `—`를 유지한다.
- 그래프 툴팁은 연도·항목·금액을 표시하는 둥근 카드로 구성하고, 금액은 표와 동일한 만원 단위로 표시한다. 마우스를 올린 영역은 연한 보라색으로 표시한다.

## 초기 인증 조회 장애 대응 (2026-11-09)

- `/api/v1/users/me` 확인 중이거나 조회에 실패해도 공통 레이아웃에서 화면 표시를 차단하지 않는다. 백엔드 없이도 프론트 화면을 실행하며, 로그인·API가 필요한 기능은 각 화면의 기존 상태 처리와 권한 확인을 따른다.
- 연결 장애를 로그아웃으로 확정하지 않는다. 오류 안내와 `다시 확인` 버튼을 제공하고, 공통 채팅 위젯은 인증 확인이 완료된 뒤 표시한다.

## 실제 차감액 화면 연결 (2026-11-03)

- 페이지가 통합 응답의 `deductedAmount`를 SummaryCards에 전달하고 총세금 카드에 `차감된 금액`으로 작게 표시한다. 만원 반올림 대신 원 단위로 표시한다.
- 실제 거래의 세전·세후 차액이며 미래 예상 차감액을 포함하지 않는다. 국내 기납부세액 또는 공제 가능한 외국 세금으로 확정하지 않는다. 총세금에서 자동 차감하지 않고 추가 납부 예상액은 준비 중으로 유지한다.
- 로딩·오류 또는 입금액 누락으로 null인 경우 `—`, 실제 차감액이 0인 경우 `0원`을 표시한다.

## 총수입·총지출 실제·예상 구분 (2026-11-03)

- 서버가 월별 실제 합계와 남은 달 예상 합계를 응답에 포함하고 페이지가 SummaryCards에 전달한다. 추가 DB 조회 없이 기존 월별 목록을 사용한다.

## 추가 납부 예상액 표시 시안 (2026-11-03)

- SummaryCards의 총세금 카드 안에 `추가 납부 예상액 — · 준비 중`을 작은 글씨 한 줄로 표시한다. 별도 구분선·큰 금액·긴 안내 블록은 제거하고 기존 3열 배치를 유지한다.
- 정산 로직은 미구현이므로 금액은 `—`로 표시한다. 정산 기능이 준비 중이라는 설명은 title에 둔다. 배치 검토 후 유지·수정 여부를 정한다.

- 2026-11-03 월별 조회 통합: `findMonthlyTransactions`가 월·거래 구분별 합계를 한 번 조회한다. 수입은 세전 금액, 지출은 실제 금액을 합산한다. 서비스에서 기존 수입·지출 응답 목록으로 나누므로 화면 형식은 유지한다. 전체 DB 조회는 기본정보·기간·월별 합계 총 3회이며 아래 4회 조회 기록을 대체한다.
- 2026-11-03 정리: 기존 breakdown·월별 개별 API와 전용 서비스 메서드·TaxDto·프론트 월별 API 함수를 제거했다. 결과 조회는 calculation-result 하나만 사용한다. 아래 과거 개별 API 유지 기록은 더 이상 적용하지 않는다.

## 세금 분석 입력 화면 (2026-10-23)

- 대상은 면세 1인 유튜버이며 올해 거래를 대상으로 계산한다. 기본정보 카드 오른쪽 위에 `올해 연도 + 년 기준`을 작게 표시하며 연도 입력칸은 두지 않는다.
- 사업자등록 여부를 받고, 미등록자는 현재 만 나이, 등록자는 올해 창업 세액감면 적용 여부를 입력한다. 감면 적용 시 창업 당시 사업장 소재지만 추가로 받으며 창업일은 받지 않는다.
- 기본정보 상단의 단계 표시는 두지 않는다. 한 카드 안에서 왼쪽은 등록 여부·조건별 추가 입력, 오른쪽은 공제·기부금으로 나란히 배치한다. 작은 화면에서는 세로로 배치한다. 등록·미등록은 작은 선택 버튼, 나이는 짧은 입력칸과 ‘세’ 단위로 표시하며 큰 색상 배경을 두지 않는다. 공제·기부금 설명은 각 입력칸 아래에 둔다.
- 창업 당시 사업장 소재지는 주소를 받지 않고 수도권 과밀억제권역(`CAPITAL_CONGESTION`)·수도권 중 과밀억제권역 외(`CAPITAL_OTHER`)·비수도권(`NON_CAPITAL`) 중 하나를 선택한다. 화면에서는 한국어로 표시한다.
- 기본공제 대상 가족 수는 본인을 제외한다. 기부금은 공제 대상 복지단체 기부금으로 안내하며 정치·종교 기부금은 제외한다.
- 직접 입력은 날짜·수입/지출·카테고리·거래 설명·실제 입출금액을 받는다. 수입은 차감 세율(기본 3.3%, 수정 가능)을 받아 세전 수입을 `실제 입금액 / (1 - 차감 세율 / 100)`으로 역산하고 원 단위 반올림한다. 세전 수입 입력칸은 두지 않는다. 차감이 없으면 0%로 입력하며 PDF는 추출값을 유지한다.
- 입력 화면의 합계는 선택한 거래의 실제 입출금액 기준이다. 미분류 금액은 카테고리가 없는 거래의 금액이며 수입·지출 합계에 이미 포함된다. 실제 입출금액이 없는 거래는 합계에서 제외하고 안내한다.
- 현재 공제·창업감면 입력값은 화면 상태에만 보관한다. 서버 저장 및 결과 계산 연결은 후속 작업이며, 기존 결과 화면은 변경하지 않는다.
- 입력 방식 전환을 제거하고 직접 입력을 기본으로 표시한다. 입력 카드 오른쪽의 작은 PDF 불러오기 버튼으로 거래를 추가하며 두 경로의 거래를 같은 목록·합계·분석에 반영한다. 거래별 반영 체크·반영 상태·전체 선택과 해제는 제거한다. 남아 있는 유효 거래를 계산하고 삭제는 휴지통을 사용한다. PDF 검증용 합계의 중복 제외 규칙은 유지한다.
- 거래 입력 카테고리는 공통 문서 `docs/creator-tax-dummy-format.md`의 영문 코드와 한글 표시명을 따른다. 수입 3종·지출 8종에 공통 기타·미분류를 제공하며 거래 상태에는 영문 코드, 선택지와 목록에는 한글 이름을 사용한다.
- 거래 목록의 금액은 실제 입출금액 한 열로 표시한다. 세전 수입과 차감 세율은 내부 계산용으로 유지하고 목록에는 별도로 표시하지 않는다.

- 로그인·로그아웃과 회원정보 변경 요청의 Bearer 헤더를 제거했다. PDF 업로드도 기존 로컬 토큰 조회·Bearer 헤더 대신 쿠키를 사용한다.
- 실제 브라우저에서 로그인, 새로고침 후 로그인 유지, 회원정보 조회, 로그아웃, 새로고침 후 비로그인을 확인했다. 자동 로그인 체크박스·토큰 발급/검증·Redis 로직은 변경하지 않았다.

- 1단계 회원 정보: 아이디·비밀번호·비밀번호 확인·이름·이메일 인증. 2단계 프로필 설정: 선택 이미지·닉네임·가입 완료.
- 다음 단계는 회원 정보와 이메일 인증 확인 후 진행하며, 이전 단계로 돌아가도 입력값과 선택한 파일을 유지한다.
- Enter는 아이디 중복 확인 후 비밀번호로 이동, 비밀번호→확인→이름→이메일 이동, 이메일 인증 요청·인증번호 확인 후 다음 버튼으로 이동, 닉네임 중복 확인 후 가입 완료 버튼으로 이동한다.
- 한글 조합 중 Enter는 이동하지 않는다. 인증번호 입력칸은 발송 성공 후 표시하며 실제 회원 생성은 2단계 최종 가입에서만 요청한다.
- 2단계 프로필 이미지는 원형 미리보기와 사진 선택·기본 이미지로 변경 버튼으로 표시한다. 파일명은 숨기고, 선택한 사진은 최종 가입 시 업로드한다. 기본 이미지로 변경하면 선택 파일을 제거한다.
- 아이디·이메일·인증번호·닉네임은 입력칸과 버튼을 같은 행에 배치하고 오류 문구는 별도 행으로 표시하여 버튼 정렬이 변하지 않도록 한다.
- 표시된 입력 오류는 다른 항목을 수정해도 유지한다. 수정한 항목만 최신 값으로 다시 검사하고 조건을 충족하면 해당 오류만 지운다. 비밀번호 변경 시 확인란 오류도 갱신하며, 이메일 인증 안내는 실제 인증 성공 후 해제한다.
- 회원가입 입력칸에는 현재 검사 조건에 맞는 안내를 표시한다: 비밀번호 8~20자·공백 금지·영문/숫자/특수문자(!@#$%^&*) 각각 포함, 비밀번호 재입력, 이름·닉네임 최대 50자, 이메일 형식 예시·최대 255자, 메일 인증번호 숫자 6자리.

## 로그인·로그아웃 실제 API 연결 (2026-10-14)

- 성공 응답의 accessToken과 서버 회원 정보는 현재 페이지 메모리에만 보관한다. 세션 스토리지 저장·복원을 제거했으며 새로고침 시 GET /users/me로 기존 JWT 쿠키 인증 상태를 확인해 화면을 복원한다.
- 로그인 화면의 실패 횟수·잠금 판단은 서버 응답을 사용한다. 브라우저 mock 잠금 시간 안내는 적용하지 않는다.
- 로그아웃: DELETE /api/v1/auth/sessions/current를 기존 JWT 쿠키로 호출하고, 성공 후 화면의 인증 상태를 비운다.
- 회원가입·계정 찾기·마이페이지 등 다른 화면은 이번 작업에서 실제 API로 연결하지 않는다.
- 이름·닉네임이 로그인 응답에 없으므로 현재 화면용 사용자 표시에는 loginId를 사용한다.
- 모델 입력·출력·계산 로직은 변경하지 않는다.

## 인증·회원 화면 실제 연결 (2026-10-15)

- 회원가입: SignupForm → userApi의 중복 확인·이메일 발송/확인·가입 요청. mock 계정 저장과 브라우저 인증번호 생성은 사용하지 않는다.
- 요청 필드: loginId, password, name, nickname, email. 프로필 선택 시 multipart의 profile 파일로 보낸다. 전화번호 입력은 제거했다.
- 인증번호 안내는 5분, 인증 완료 후 가입 안내는 10분이며, 최종 유효성은 서버가 판단한다. 이메일을 바꾸면 화면의 이전 인증 상태를 초기화한다.
- 계정 찾기: 이름·이메일·인증번호로 로그인 아이디를 조회하고, 인증 완료 후 전체 아이디를 표시한다. 결과창에는 이메일을 표시하지 않으며, 로그인하기·비밀번호 찾기 버튼으로 각 화면에 이동한다. 비밀번호 찾기는 연한 보라색 배경·글자·테두리로 닫기 버튼과 구분한다.
- 아이디·비밀번호 찾기의 인증번호 발송 성공 응답부터 60초간 발송 버튼을 비활성화하고 남은 초를 표시한다. 재발송 실패 시 기존 인증 상태와 유효시간을 유지한다.
- 비밀번호 재설정: 계정과 이메일 일치 및 메일 인증 후 서버에 새 비밀번호를 전송한다. 성공하면 기존 Redis 세션도 종료한다.
- 마이페이지 회원 정보: GET /users/me로 읽고 닉네임·인증한 이메일·비밀번호·프로필 이미지 변경을 연결했다. 저장 성공 후 서버 정보를 다시 조회해 스토어를 갱신한다.
- 탈퇴: 복구 불가 경고의 확인 체크와 현재 비밀번호 입력 후에만 회원 삭제 버튼으로 DELETE /users/me를 요청한다. 성공 후 브라우저 인증 상태를 비운다. FK에 연결된 데이터가 있으면 서버 오류 안내를 표시하며 다른 테이블을 임의로 삭제하지 않는다.
- 모든 회원 요청은 api/userApi.js → 공통 client → /api/v1 경로를 사용한다. 인증이 필요한 요청은 브라우저의 기존 HttpOnly JWT 쿠키로 인증하며 프론트는 Bearer 헤더를 만들지 않는다.
- 대기 중 중복 요청을 막고 실패 메시지를 표시한다. 서버의 error.fields는 각 입력 필드에 연결한다.
- 계정 찾기·재설정 API 상세 경로와 JSON은 루트 docs/api-draft.md를 기준으로 한다.
- 실제 검증: 이메일 발송·인증, 생년월일 없이 가입, 로그인, 아이디 찾기, 비밀번호 재설정 및 기존 토큰 거부, 프로필 조회·닉네임/비밀번호/이미지 변경, 미인증 이메일 변경 거부, 인증 후 현재 이메일 저장, 임시 계정 탈퇴 및 이후 로그인 거부를 확인했다.
- 서로 다른 이메일 주소로 바꾸는 실제 발송 검증은 별도 필요하다. 이번 실제 이메일 저장 테스트는 같은 주소로 인증 후 저장하는 흐름을 확인했다.
- 세금 계산·게시글·관리자 등 다른 기능은 이번 연동 대상이 아니다.

## PDF 업로드 대기·오류 표시 수정 (2026-10-16)

- 기존 업로드 컴포넌트의 안내를 텍스트·이미지 PDF 분석 흐름에 맞췄다.
- 파일별 실패 원인은 토스트 외에 업로드 영역에도 남긴다. 새 업로드를 시작하면 이전 오류를 지운다.
- 요청 대기 중단 시 진행 중인 HTTP 대기와 남은 파일 전송을 중단한다. 서버에서 이미 저장한 자료의 취소·삭제는 보장하지 않는다.
- 대기 중 파일당 최대 2분 안내를 표시한다. 시간 초과 시 오류를 표시하고 파일 선택을 다시 활성화한다.

## PDF 전체 항목 검토 (2026-10-16)

- 상세·월별·연간 합계·검증용·미분류·0원 항목 모두 수정 입력칸을 제공한다. 0원은 수정 가능하며 거래 저장은 양수 금액만 허용한다.
- 거래일은 추정하지 않는다. 날짜가 없으면 사용자가 선택한 연도의 실제 날짜를 입력한다.
- 저장 시 계산 포함 여부는 기본 해제이며 사용자가 선택한다. 집계 항목을 포함하려면 중복 여부 확인이 필요하다.
- 누락 내역 직접 추가, 항목 제외·복원, 저장된 검토 거래 재수정을 지원한다. 제외는 현재 계산 목록에만 적용하며 서버 기록은 삭제하지 않는다.
- 회원은 기존 POST로 최초 저장하고 PUT으로 수정한다. 비회원은 현재 화면에서만 유지한다.

## PDF 자동 불러오기 (2026-10-16)

- 추출 후보를 업로드 직후 PDF 목록에 자동 표시한다. 사용자 저장 전에는 계산에 포함하지 않는다.
- 인식된 날짜·구분·카테고리·내용·금액은 입력칸에 채우고 알 수 없는 값은 빈칸으로 둔다. 월별 집계에서 임의 날짜를 만들지 않는다.
- 불완전한 후보는 `입력 필요`로 표시한다. 확인 저장 시 같은 행을 갱신하며 중복 생성하지 않는다.

## PDF 자동 추천과 계산 버튼 안내

- 카드 사용액·지출 등의 구분은 지출로 자동 추천하며 카테고리는 원문 값이 없으면 교통·출장 또는 기타 경비 등 편집 가능한 추천값을 표시한다. 세법상 경비 인정의 확정은 아니다.
- 거래일이 없는 집계는 날짜를 임의 생성하지 않으며 입력 이유를 안내한다.
- 계산 버튼은 확인·선택된 행이 있으면 계산 화면으로 이동한다. 없으면 오류를 표시하고 검토 입력칸으로 이동한다. 개별 상세 항목은 저장 시 계산 포함을 기본 선택하고 집계는 명시적으로 선택한다.

## PDF 월별 초기값·수정

- 월별 집계는 `transactionMonth`를 월 입력칸에 자동 표시하며 일자를 요구하지 않는다. 구분·추천 카테고리·내용·금액은 기존 초기값을 유지하고 모두 수정 가능하다.
- 월별 수정값은 현재 브라우저 계산 목록에 반영한다. 개별 거래일이 필요한 기존 거래 DB에는 저장하지 않으며 화면에서 안내한다. 개별 거래의 기존 저장 API는 유지한다.
- 집계의 계산 포함은 사용자 선택과 중복 확인 후 적용한다. 연간 합계와 상세 금액을 자동으로 함께 선택하지 않는다.
- PDF에서 읽은 월의 실제 입력 금액은 이후 월이어도 예측치로 덮어쓰지 않는다.

## PDF 즉시 계산 연결

- 날짜·연월, 구분, 금액을 인식한 월별 집계·상세 항목은 건별 저장 전에도 계산 가능하다. 편집 중인 값은 현재 계산 목록에 즉시 반영하며 DB 저장과 분리한다.
- 한 문서에 월 집계가 있으면 월 집계를 자동 선택하고 연간·검증 합계는 자동 선택하지 않는다. 월 집계가 없으면 상세 항목을 자동 선택한다. 사용자가 선택을 바꿀 수 있다.
- 일자가 있는 날짜는 년·월·일 전체를 표시한다. 월 집계는 일자를 생성하지 않는다. 파싱은 하이픈·슬래시·점·한국어 년월일 표기를 지원한다.

## PDF 자동 입력·최종 확인 흐름

- 개별 거래는 실제 거래일, 월별 집계는 연월, 연간 집계는 원문 귀속연도만 표시·수정한다. 연간 집계에 거래일을 요구하지 않는다.
- 월별 내역이 있으면 월별을, 없으면 상세를, 둘 다 없으면 항목별 연간 합계를 우선 선택한다. 전체 합계는 대조용으로 계산에서 제외한다.
- 같은 문서에서 연간·월별·상세 수준을 함께 선택하면 계산을 막고 중복 선택을 안내한다.
- 문서별 최종 확인에서 원본 대조·사업 관련성·중복 여부를 확인해야 계산으로 이동한다. 편집·선택 변경 시 최종 확인을 해제한다.
- 카드 사용액의 지출 구분과 추천 카테고리는 세법상 경비 인정의 확정이 아니다. 현재 계산은 사업소득 추정 계산이며 연말정산 공제액 계산을 새로 구현한 것은 아니다.
- 연간 금액은 연간 총액에만 반영하며 월별 차트용 임의 배분은 하지 않는다. 집계 수정값은 현재 브라우저에서 관리하고 기존 실제 거래일 필수 DB에는 저장하지 않는다.

## 계산 버튼 최종 확인 표시 수정

- PDF 계산 버튼을 누르면 버튼 바로 아래에서 최종 확인을 진행한다. 화면 아래 문서 확인란으로 이동하고 멈추던 흐름을 제거했다.

## 시뮬레이션 계산 연결 (2026-11-06)

- 입력 순서는 추가 세전 수입·추가 사업 지출·추가 기부금이다. 노란우산 입력은 제거한다.

## 회원·귀속연도별 저장 결과 교체 (TJK-230)

- 같은 분석번호로 다시 저장하면 결과 JSON만 갱신하고 현재 분석의 입력·거래·시나리오는 유지한다.
- 회원번호 기록·이전 저장 분석 삭제·현재 결과 JSON 저장을 같은 트랜잭션에서 처리한다.

## 마이페이지 저장 결과 목록 (TJK-231)

- 목록 위에 귀속연도별 총수입·총지출·총세금 비교 카드를 표시한다. 표가 기본이며 오른쪽 위 버튼으로 그래프와 전환한다.

- 인증된 회원번호로 본인의 저장 결과만 조회하며, 귀속연도·최근 저장일·결과 보기·시뮬레이션 버튼을 표시한다.
