# 모델 카드

## 총수입·총지출 카드 Spring 연결 (2026-10-29)

- 기존 요약 카드 배치를 유지하고 `SummaryCards`가 분석번호로 총수입·총지출 API를 호출한다.
- 실제·예상 합계는 서버에서 계산하며 카드에서는 만원 단위로 표시한다. 수입·지출 차액도 같은 조회 결과로 표시한다.
- 수입·지출 카드에는 ‘실제·예상 금액 합계’를 표시하고, 수입·지출 차액은 총세금 카드에 표시한다.
- ‘입력한 지출 전액을 필요경비로 가정합니다.’라는 계산 가정은 세 카드 아래 공통 안내로 표시한다.
- 로딩·오류를 표시하며 API 실패를 0원이나 예시 금액으로 대체하지 않는다. 총세금·산출 근거·결과 저장은 기존 계산 방식을 유지한다.

## 월별 그래프 Spring 연결 (2026-10-29)

- 결과 전용 컴포넌트는 `src/components/calculator/result/`에 모은다. 요약 카드·산출 근거·월별 그래프·등록 비교를 포함한다. 입력·시뮬레이션 컴포넌트는 기존 위치를 유지한다.
- 결과 화면의 ‘다음에 할 일’ 안내와 안내용 절감액 계산은 제거한다.

- 결과 화면의 기존 카드 한 개 안에 월별 수입·지출 막대를 나란히 표시한다. 기존 SVG 코드의 좌표·막대 너비·간격·예측 구간 배경을 유지한다.
- `MonthlyChart` 하나가 분석번호를 props로 받아 API 호출·데이터·로딩·오류 관리와 그래프 표시를 담당한다. 결과 페이지는 분석번호 전달과 영역 배치만 맡는다. 서버 금액을 다시 계산하지 않는다.
- 목록 항목은 `month`, `amount`, `predicted`이고, 기존처럼 실제 막대는 색을 채우고, 예상 막대는 속을 비우고 점선 테두리로 표시한다. 예측 구간 배경은 첫 예상 월부터 표시한다.
- Y축은 최고 금액을 기준으로 1·2·5·10 계열의 간격을 정해 4칸으로 표시한다. 눈금 단위는 축 최댓값에 따라 원·만원·억원으로 바꾸며 실제 금액은 변경하지 않는다.
- 월별 그래프는 Spring 월별 수입·지출 API를 호출해 실제 DB 조회 및 서버 예상 계산 결과를 표시한다. 임시 예시 데이터는 제거했다.
- 결과 페이지에서 테스트 분석번호 `19`를 전달한다. 이후 이 값을 입력창에서 발급받은 분석번호로 교체한다. 다른 결과 카드·저장·시뮬레이션은 기존 동작을 유지한다.

## 세액 산출 결과 표시 변경 (2026-10-27)

- 결과 요약과 산출 근거를 추가납부·환급액에서 총 세금(소득세와 지방소득세 합계)으로 변경한다.
- 결과 화면의 계산·저장·비교는 기납부세액을 차감하지 않는 같은 기준을 사용한다.
- 기존 예시 세율·공제 계산은 유지하며, 올해 세법 검증이나 기본정보 공제·감면 입력의 계산 연결이 완료됐다는 뜻은 아니다.
- 별도 시뮬레이션 화면은 기존 차액 계산과 표시를 유지한다. 결과 화면과 기준을 통일하는 작업은 별도로 필요하다.

## 세금 분석 입력 화면 (2026-10-23)

- 대상은 면세 1인 유튜버이며 올해 거래를 대상으로 계산한다. 기본정보 카드 오른쪽 위에 `올해 연도 + 년 기준`을 작게 표시하며 연도 입력칸은 두지 않는다.
- 사업자등록 여부를 받고, 미등록자는 현재 만 나이, 등록자는 올해 창업 세액감면 적용 여부를 입력한다. 감면 적용 시 창업 당시 사업장 소재지만 추가로 받으며 창업일은 받지 않는다.
- 기본정보 상단의 단계 표시는 두지 않는다. 한 카드 안에서 왼쪽은 등록 여부·조건별 추가 입력, 오른쪽은 공제·기부금으로 나란히 배치한다. 작은 화면에서는 세로로 배치한다. 등록·미등록은 작은 선택 버튼, 나이는 짧은 입력칸과 ‘세’ 단위로 표시하며 큰 색상 배경을 두지 않는다. 공제·기부금 설명은 각 입력칸 아래에 둔다.
- 창업 당시 사업장 소재지는 주소를 받지 않고 수도권 과밀억제권역(`CAPITAL_CONGESTION`)·수도권 중 과밀억제권역 외(`CAPITAL_OTHER`)·비수도권(`NON_CAPITAL`) 중 하나를 선택한다. 화면에서는 한국어로 표시한다.
- 기본공제 대상 가족 수는 본인을 제외한다. 기부금은 공제 대상 복지단체 기부금으로 안내하며 정치·종교 기부금은 제외한다.
- 직접 입력은 날짜·수입/지출·카테고리·거래 설명·실제 입출금액을 받는다. 수입은 차감 세율(기본 3.3%, 수정 가능)을 받아 세전 수입을 `실제 입금액 / (1 - 차감 세율 / 100)`으로 역산하고 원 단위 반올림한다. 세전 수입 입력칸은 두지 않는다. 차감이 없으면 0%로 입력하며 PDF는 추출값을 유지한다.
- 입력 화면의 합계는 선택한 거래의 실제 입출금액 기준이다. 미분류 금액은 카테고리가 없는 거래의 금액이며 수입·지출 합계에 이미 포함된다. 실제 입출금액이 없는 거래는 합계에서 제외하고 안내한다.
- 현재 공제·창업감면 입력값은 화면 상태에만 보관한다. 서버 저장 및 결과 계산 연결은 후속 작업이며, 기존 결과 화면은 변경하지 않는다.
- 입력 방식 전환을 제거하고 직접 입력을 기본으로 표시한다. 입력 카드 오른쪽의 작은 PDF 불러오기 버튼으로 거래를 추가하며 두 경로의 거래를 같은 목록·합계·분석에 반영한다. 거래별 반영 체크·반영 상태·전체 선택과 해제는 제거한다. 남아 있는 유효 거래를 계산하고 삭제는 휴지통을 사용한다. PDF 검증용 합계의 중복 제외 규칙은 유지한다.
- 거래 입력 카테고리는 공통 문서 `docs/creator-tax-dummy-format.md`의 영문 코드와 한글 표시명을 따른다. 수입 3종·지출 8종에 공통 기타·미분류를 제공하며 거래 상태에는 영문 코드, 선택지와 목록에는 한글 이름을 사용한다.
- 거래 목록의 금액은 실제 입출금액 한 열로 표시한다. 세전 수입과 차감 세율은 내부 계산용으로 유지하고 목록에는 별도로 표시하지 않는다.

- 기존 서버의 목록 조회·해제 API를 사용하며 서버 정책은 변경하지 않는다.

## 로그인 실패·관리자 해제 (2026-10-16)

- 서버 정책: 6회 30초 → 7회 1분 → 8회 3분 → 9회 5분 → 10회 LOCKED. 차단 중 시도는 횟수·시간을 변경하지 않는다.
- 로그인 성공·관리자 해제 시만 실패 기록을 초기화하며, 관리자 정지 BANNED와 실패 잠금 LOCKED를 구분한다.
- 로그인 버튼을 눌렀을 때 받은 서버 응답으로만 카운트다운과 잠금 안내를 표시한다. 아이디 입력 중 자동 조회나 매초 서버 요청은 하지 않는다.
- 관리자 회원 관리 탭에 실제 제한 계정 목록·해제 영역을 추가했다. 기존 예시 회원 관리와 구분한다.
- 기존 쿠키 인증·자동 로그인은 유지한다. 실패 이메일·이메일 잠금 해제는 사용하지 않는다.

## URL 변경 시 로그인 상태 확인 (2026-10-15)

- 최초 실행은 기존 checkAuth로 확인한다. 이후 로그인 중 경로나 쿼리가 변경되면 Layout에서 refreshProfile로 GET /users/me를 호출한다.
- 401이면 기존 스토어 처리로 로그인 정보를 비우고, 통신·서버 장애는 로그인 정보를 유지한다. 확인 실패는 안내 메시지로 표시한다.
- 마이페이지의 진입 시 별도 회원 조회는 제거해 공통 확인과 중복되지 않게 한다. 회원 정보 수정 후 재조회는 유지한다.
- 쿠키 인증을 유지하며 창 복귀 이벤트나 주기적 확인은 추가하지 않는다.

## 인증 화면 이동 수정 (2026-10-15)

- 로그인 화면 내부의 회원가입·계정 찾기 링크도 URL로 이동한다. 표시할 화면은 URL에서 계산한다.
- 내부 회원가입 이동 후 헤더 로그인 클릭 시 /login으로 돌아온다. 계정 찾기는 /find-account의 tab 쿼리로 아이디·비밀번호 찾기를 구분한다.
- 인증 방식과 자동 로그인 요청은 변경하지 않는다.

## 로그인 자동 로그인 선택 (2026-10-15)

- 로그인 화면의 자동 로그인 체크값을 로그인 API의 rememberMe로 전달한다. 기본값은 미선택(false)이다.
- 인증은 기존 HttpOnly JWT 쿠키를 사용하며, 선택값이나 토큰을 브라우저 저장소에 추가로 저장하지 않는다.

## 기존 JWT 쿠키 인증 연결 (2026-10-15)

- JWT는 프론트 상태·sessionStorage·localStorage에 보관하지 않고, 브라우저가 기존 HttpOnly 쿠키를 자동 전달한다.
- 첫 화면에서 GET /users/me로 로그인 상태를 확인하며, 조회 중에는 확인 안내를 표시한다. 401은 비로그인, 네트워크·서버 장애는 오류 및 재시도로 구분한다.
- 로그인·로그아웃과 회원정보 변경 요청의 Bearer 헤더를 제거했다. PDF 업로드도 기존 로컬 토큰 조회·Bearer 헤더 대신 쿠키를 사용한다.
- 실제 브라우저에서 로그인, 새로고침 후 로그인 유지, 회원정보 조회, 로그아웃, 새로고침 후 비로그인을 확인했다. 자동 로그인 체크박스·토큰 발급/검증·Redis 로직은 변경하지 않았다.

## 세션 스토리지 제거 (2026-10-15)

- 로그인 JWT·회원 정보와 기존 mock 아이디를 세션 스토리지에 저장하거나 복원하지 않는다.
- 로그인 후 복귀 주소도 페이지 메모리에만 보관한다.
- 앱 시작 시 이전 버전이 남긴 세 키만 삭제한다. JWT 쿠키와 Redis는 변경하지 않으며 화면은 GET /users/me로 쿠키 인증 결과를 조회해 복원한다.

## 비밀번호 조건 통일 (2026-10-15)

- 회원가입·마이페이지 비밀번호 변경·계정 찾기 비밀번호 재설정에 동일하게 8~20자, 공백 금지, 영문·숫자·특수문자(!@#$%^&*) 각각 하나 이상 포함 조건을 적용한다.
- 새 비밀번호 검사만 공유하며, 로그인과 현재 비밀번호 대조에는 새 조건을 적용하지 않는다.

## 회원가입 생년월일 입력 (2026-10-15)

- 선택 항목이며 숫자 8자리(예: 19980521)를 입력하면 1998.05.21로 표시한다.
- 입력하지 않으면 null, 입력하면 실제 날짜인지 확인하고 기존 birthDate 형식인 YYYY-MM-DD로 서버에 전달한다.

## 회원가입 단계와 키보드 이동 (2026-10-15)

- 회원가입 제목과 22px 아이콘을 한 줄로 표시하고 상단 여백을 줄인다. 로그인·계정 찾기 화면 배치는 유지한다.

- 1단계 회원 정보: 아이디·비밀번호·비밀번호 확인·이름·이메일 인증. 2단계 프로필 설정: 선택 이미지·닉네임·선택 생년월일·가입 완료.
- 다음 단계는 회원 정보와 이메일 인증 확인 후 진행하며, 이전 단계로 돌아가도 입력값과 선택한 파일을 유지한다.
- Enter는 아이디 중복 확인 후 비밀번호로 이동, 비밀번호→확인→이름→이메일 이동, 이메일 인증 요청·인증번호 확인 후 다음 버튼으로 이동, 닉네임 중복 확인 후 생년월일로 이동, 생년월일에서 최종 가입으로 처리한다.
- 한글 조합 중 Enter는 이동하지 않는다. 인증번호 입력칸은 발송 성공 후 표시하며 실제 회원 생성은 2단계 최종 가입에서만 요청한다.
- 2단계 프로필 이미지는 원형 미리보기와 사진 선택·기본 이미지로 변경 버튼으로 표시한다. 파일명은 숨기고, 선택한 사진은 최종 가입 시 업로드한다. 기본 이미지로 변경하면 선택 파일을 제거한다.
- 아이디·이메일·인증번호·닉네임은 입력칸과 버튼을 같은 행에 배치하고 오류 문구는 별도 행으로 표시하여 버튼 정렬이 변하지 않도록 한다.
- 표시된 입력 오류는 다른 항목을 수정해도 유지한다. 수정한 항목만 최신 값으로 다시 검사하고 조건을 충족하면 해당 오류만 지운다. 비밀번호 변경 시 확인란 오류도 갱신하며, 이메일 인증 안내는 실제 인증 성공 후 해제한다.
- 회원가입 입력칸에는 현재 검사 조건에 맞는 안내를 표시한다: 비밀번호 8~20자·공백 금지·영문/숫자/특수문자(!@#$%^&*) 각각 포함, 비밀번호 재입력, 이름·닉네임 최대 50자, 이메일 형식 예시·최대 255자, 메일 인증번호 숫자 6자리.

## 인증·회원 화면 실제 연결 (2026-10-15)

- 회원가입: SignupForm → userApi의 중복 확인·이메일 발송/확인·가입 요청. mock 계정 저장과 브라우저 인증번호 생성은 사용하지 않는다.

- 계정 찾기: 이름·이메일·인증번호로 로그인 아이디를 조회하고 화면에서 마스킹한다.
- 비밀번호 재설정: 계정과 이메일 일치 및 메일 인증 후 서버에 새 비밀번호를 전송한다. 성공하면 기존 Redis 세션도 종료한다.

- 탈퇴: 복구 불가 경고의 확인 체크와 현재 비밀번호 입력 후에만 회원 삭제 버튼으로 DELETE /users/me를 요청한다. 성공 후 브라우저 인증 상태를 비운다. FK에 연결된 데이터가 있으면 서버 오류 안내를 표시하며 다른 테이블을 임의로 삭제하지 않는다.
- 모든 회원 요청은 api/userApi.js → 공통 client → /api/v1 경로를 사용한다. 인증이 필요한 요청은 브라우저의 기존 HttpOnly JWT 쿠키로 인증하며 프론트는 Bearer 헤더를 만들지 않는다.
- 대기 중 중복 요청을 막고 실패 메시지를 표시한다. 서버의 error.fields는 각 입력 필드에 연결한다.
- 계정 찾기·재설정 API 상세 경로와 JSON은 루트 docs/api-draft.md를 기준으로 한다.
- 실제 검증: 이메일 발송·인증, 생년월일 없이 가입, 로그인, 아이디 찾기, 비밀번호 재설정 및 기존 토큰 거부, 프로필 조회·닉네임/비밀번호/이미지 변경, 미인증 이메일 변경 거부, 인증 후 현재 이메일 저장, 임시 계정 탈퇴 및 이후 로그인 거부를 확인했다.
- 서로 다른 이메일 주소로 바꾸는 실제 발송 검증은 별도 필요하다. 이번 실제 이메일 저장 테스트는 같은 주소로 인증 후 저장하는 흐름을 확인했다.

## PDF 전체 항목 검토 (2026-10-16)

- 상세·월별·연간 합계·검증용·미분류·0원 항목 모두 수정 입력칸을 제공한다. 0원은 수정 가능하며 거래 저장은 양수 금액만 허용한다.

- 회원은 기존 POST로 최초 저장하고 PUT으로 수정한다. 비회원은 현재 화면에서만 유지한다.

## PDF 자동 불러오기 (2026-10-16)

- 추출 후보를 업로드 직후 PDF 목록에 자동 표시한다. 사용자 저장 전에는 계산에 포함하지 않는다.
- 인식된 날짜·구분·카테고리·내용·금액은 입력칸에 채우고 알 수 없는 값은 빈칸으로 둔다. 월별 집계에서 임의 날짜를 만들지 않는다.
- 불완전한 후보는 `입력 필요`로 표시한다. 확인 저장 시 같은 행을 갱신하며 중복 생성하지 않는다.

## PDF 자동 추천과 계산 버튼 안내

- 카드 사용액·지출 등의 구분은 지출로 자동 추천하며 카테고리는 원문 값이 없으면 교통·출장 또는 기타 경비 등 편집 가능한 추천값을 표시한다. 세법상 경비 인정의 확정은 아니다.
- 거래일이 없는 집계는 날짜를 임의 생성하지 않으며 입력 이유를 안내한다.
- 계산 버튼은 확인·선택된 행이 있으면 계산 화면으로 이동한다. 없으면 오류를 표시하고 검토 입력칸으로 이동한다. 개별 상세 항목은 저장 시 계산 포함을 기본 선택하고 집계는 명시적으로 선택한다.

## PDF 월별 초기값·수정

- 월별 집계는 `transactionMonth`를 월 입력칸에 자동 표시하며 일자를 요구하지 않는다. 구분·추천 카테고리·내용·금액은 기존 초기값을 유지하고 모두 수정 가능하다.
- 월별 수정값은 현재 브라우저 계산 목록에 반영한다. 개별 거래일이 필요한 기존 거래 DB에는 저장하지 않으며 화면에서 안내한다. 개별 거래의 기존 저장 API는 유지한다.
- 집계의 계산 포함은 사용자 선택과 중복 확인 후 적용한다. 연간 합계와 상세 금액을 자동으로 함께 선택하지 않는다.
- PDF에서 읽은 월의 실제 입력 금액은 이후 월이어도 예측치로 덮어쓰지 않는다.

## PDF 즉시 계산 연결

- 날짜·연월, 구분, 금액을 인식한 월별 집계·상세 항목은 건별 저장 전에도 계산 가능하다. 편집 중인 값은 현재 계산 목록에 즉시 반영하며 DB 저장과 분리한다.
- 한 문서에 월 집계가 있으면 월 집계를 자동 선택하고 연간·검증 합계는 자동 선택하지 않는다. 월 집계가 없으면 상세 항목을 자동 선택한다. 사용자가 선택을 바꿀 수 있다.
- 일자가 있는 날짜는 년·월·일 전체를 표시한다. 월 집계는 일자를 생성하지 않는다. 파싱은 하이픈·슬래시·점·한국어 년월일 표기를 지원한다.

## PDF 자동 입력·최종 확인 흐름

- 개별 거래는 실제 거래일, 월별 집계는 연월, 연간 집계는 원문 귀속연도만 표시·수정한다. 연간 집계에 거래일을 요구하지 않는다.
- 월별 내역이 있으면 월별을, 없으면 상세를, 둘 다 없으면 항목별 연간 합계를 우선 선택한다. 전체 합계는 대조용으로 계산에서 제외한다.
- 같은 문서에서 연간·월별·상세 수준을 함께 선택하면 계산을 막고 중복 선택을 안내한다.
- 문서별 최종 확인에서 원본 대조·사업 관련성·중복 여부를 확인해야 계산으로 이동한다. 편집·선택 변경 시 최종 확인을 해제한다.
- 카드 사용액의 지출 구분과 추천 카테고리는 세법상 경비 인정의 확정이 아니다. 현재 계산은 사업소득 추정 계산이며 연말정산 공제액 계산을 새로 구현한 것은 아니다.
- 연간 금액은 연간 총액에만 반영하며 월별 차트용 임의 배분은 하지 않는다. 집계 수정값은 현재 브라우저에서 관리하고 기존 실제 거래일 필수 DB에는 저장하지 않는다.

## 계산 버튼 최종 확인 표시 수정

- PDF 계산 버튼을 누르면 버튼 바로 아래에서 최종 확인을 진행한다. 화면 아래 문서 확인란으로 이동하고 멈추던 흐름을 제거했다.
- 최신 선택값의 중복 여부를 먼저 검사하고, 사용자가 원본·사업 관련성 확인 버튼을 누르면 로딩·결과 화면으로 이동한다. 이전에 확인한 문서만 선택되어 있으면 바로 계산으로 이동한다.

## 전체 합계 선택 전환

- 전체 합계도 계산 포함을 선택할 수 있다. 선택하면 같은 문서의 다른 합계·항목별·월별·상세 금액을 자동 해제한다. 다른 항목을 선택하면 해당 문서의 전체 합계를 해제한다.
- 문서가 다른 항목에는 영향을 주지 않는다. 표의 체크박스·수정칸·수정 저장에 같은 선택 규칙을 적용한다. 전체 선택·파일 선택도 문서별 중복되지 않는 기준을 유지한다.
