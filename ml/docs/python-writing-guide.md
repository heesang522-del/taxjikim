# Python 코드 작성·설명 기준

2026-10-27 사용자와 코드 예시를 읽으며 확인한 기준이다.
ML 코드를 추가·수정할 때 이 문서를 먼저 확인한다. 새로운 문법의 이해 수준을 임의로 가정하지 않는다.
기존 파일 전체를 이 기준으로 일괄 재구성하지 않고, 작업하는 부분에 적용한다.

## 확인한 이해 수준

| 항목 | 확인한 내용 | 작성·설명 방식 |
| --- | --- | --- |
| 조건문·반복문 | `for`, `if`, `continue`의 흐름을 읽을 수 있음 | 일반적인 반복문과 조건문 사용 |
| 딕셔너리 조회 | `row["category"]`, `row["description"]`을 이해함 | 낯선 데이터 이름은 한글 의미 설명 |
| 함수 | 매개변수에 전달한 값과 반환값의 관계를 읽을 수 있음 | 역할이 분명한 이름과 한 줄 기능 설명 |
| 파일 읽기 | `read()`와 `with`의 자동 닫기를 기억함. 직접 작성은 어려움 | 파일 열기·읽기·닫힘을 예시와 함께 설명 |
| 예외 처리 | `try` 실행 후 예외 발생 시 `except`로 이동하는 흐름을 이해함 | 잡는 예외 종류와 출력·반환의 차이를 필요할 때 설명 |
| 다른 파일의 함수 사용 | `from ... import ...`를 이해함 | 경로 인자와 파일에서 읽은 결과 데이터를 구분해 설명 |
| 리스트 컴프리헨션 | 짧은 표현도 읽을 수 있으나 풀어 쓴 반복문을 선호함 | 새 코드는 일반 `for`와 `append()` 우선 |
| 타입 힌트 | 표기의 의미를 설명받아야 함 | 입력·반환 타입을 한국어로 짧게 설명 |

`description`은 거래 설명이라는 데이터 이름이다. 영어 데이터 이름을 모르는 것을 문법 이해 부족으로 판단하지 않는다.
직접 작성할 수 있는 수준과 코드를 읽고 이해하는 수준도 구분한다.

## 타입 힌트 설명 예시

```python
# path: CSV 파일 경로, 반환값: 각 행을 딕셔너리로 담은 목록
def read_csv(path: Path) -> list[dict[str, str]]:
    """CSV 파일을 읽어 행 목록으로 반환한다."""
```

- `path: Path`: path 매개변수에 파일 경로 객체를 받는다는 표시.
- `->`: 화살표 함수가 아니라 반환값 타입을 안내하는 표시.
- `list[dict[str, str]]`: 문자열 키·문자열 값을 가진 딕셔너리들의 목록.
- 타입 힌트 자체가 값을 변환하거나 입력을 자동 검증하는 것은 아니다.

## 주석과 코드 형태

- 함수 위나 함수 첫 줄에 무슨 기능인지 한국어 한 줄로 적는다.
- 낯선 타입 표기·외부 라이브러리·파일 처리에는 필요한 설명을 짧게 덧붙인다.
- 상태 변경·데이터 흐름·계산에는 왜 필요한지 한국어 주석을 적는다.
- 이미 읽을 수 있는 문법까지 매 줄 길게 풀이하지 않는다.
- 한 줄에 여러 처리를 압축하지 않고 중간 변수와 일반 `if`, `for`를 사용한다.
- 타입 힌트는 프로젝트 컨벤션에 맞게 유지하고, 어려운 표기는 설명으로 보완한다.

선호하는 예시:

```python
# 거래 목록에서 학습에 사용할 설명만 모은다.
descriptions = []

for row in rows:
    descriptions.append(row["description"])
```

## 대화하며 확인하는 방법

- 코드 질문은 여러 개를 한꺼번에 나열하지 않고 한 예시씩 보여준다.
- 들여쓰기와 빈 줄을 유지한 코드 블록으로 보여준다.
- 답을 듣고 필요한 부분만 바로잡은 뒤 다음 예시로 넘어간다.
- 새 코드도 한 함수씩 설명하며 이해 여부를 확인한다.
- 클래스·데코레이터·비동기·프로세스 실행·스케줄러 라이브러리의 이해 수준은 아직 확인하지 않았다.
  사용이 필요하면 먼저 작은 예시로 확인하고 이 문서를 갱신한다.
