# 집에서 이어하기 — 지출 더미데이터 작업 인계

작성일: 2026-10-21. 이 문서는 다음 작업자가 현재 상태를 확인하고 이어가기 위한 안내다. 아래 기록은 새 작업·재학습·커밋·push의 자동 승인을 뜻하지 않는다.

## 1. 지금 하려는 일

**지출 카테고리 분류용 설명·정답 데이터를 다양하게 만드는 중이다.** 수입도 별도 모델을 만들 계획이지만, 지출 데이터·학습·평가를 먼저 진행한다.

사용자는 Python·ML 입문자다. 파일과 구조를 임의로 크게 바꾸지 말고, 단계마다 무엇을 만들었는지 쉽게 설명한다. 실행 명령을 먼저 알려주고 사용자가 직접 학습 결과를 볼 수 있게 한다. CSV 검토가 힘드니 설명·한글 정답만 대화에 표로 보여주는 방식을 선호한다.

## 2. 먼저 확인할 Git 상태

- 작업 브랜치: `feature/khs`. 마지막 작업 시 이 브랜치에 있었다. 시작할 때 실제 현재 브랜치와 변경 목록을 다시 확인한다.
- 마지막 확인한 공유 커밋: `e4dd47a`(TJK-158 더미 생성), `ddc49c1`(TJK-126 분류 설계·실험), `b5df5a6`(인증 임시 작업).
- 그 뒤 만든 **확장 초안 v4 관련 수정은 이 문서 작성 시점에 아직 커밋·push하지 않았다.** 집에서 저장소를 받았다고 최신 확장 코드가 자동으로 있는 것은 아니다. 아래 파일과 `--expanded-draft` 옵션 존재 여부를 확인한다.
- TJK-154는 Python 환경 설정 티켓이다. 더미 생성은 **TJK-158**, 지출 모델은 **TJK-126**이다. 앞으로 커밋을 요청받으면 티켓을 섞지 않는다.
- 커밋·push 전에는 루트 `docs/git-rule.md`를 읽고, 사용자 요청 범위만 반영한다. 이 인계 문서를 근거로 브랜치 전환·이력 수정·push를 임의 실행하지 않는다.

## 3. 합의한 입력·분류 기준

- 모델 입력은 **거래 설명 `description` 하나**다. 거래처를 추가로 요구하지 않는다. 금액·날짜·ID·정답 코드는 모델 입력에 넣지 않는다.
- 수입·지출 모델은 각각 하나씩 선택할 계획이다. LogisticRegression·LinearSVC는 비교 후보이며 지출에 두 모델을 계속 동시에 사용하는 계획이 아니다.
- 내부 코드·API·DB·학습 정답은 영문 코드, 화면 표시는 한글이다.
- 설명이 `물품 구매`처럼 모호하면 특정 카테고리 정답을 억지로 부여하지 않는다. 실제 원문에 없는 업무 목적·품목을 만들어 보충하지 않는다.
- 콘텐츠 분야는 여행·먹방·게임·일상·리뷰 등 다양하게 포함하지만 분야별 모델을 따로 만드는 계획은 아니다. 분야명만 바꾼 문장을 독립적인 거래 유형으로 세지 않는다.

| 코드 | 한글 의미·합의한 범위 |
| --- | --- |
| SOFTWARE_LICENSE | 소프트웨어: 프로그램·음원 라이선스·클라우드 저장 서비스·게임 구매 및 이용권 |
| EQUIPMENT | 하드웨어: 촬영·편집 기기와 리뷰용 전자기기 구매 |
| TELECOMMUNICATION | 통신비: 전화·인터넷 회선·데이터·로밍 요금 |
| TRANSPORT | 교통비: 이동 운임·주차료·통행료 |
| SUPPLIES_PROPS | 소모품·소품: 연출 재료·장식물·촬영용 음식과 식재료 |
| SPACE_RENTAL | 공간 대여: 촬영·녹음 공간 대관과 촬영 출장 숙박 |
| OUTSOURCING | 외주비: 외부 작업자에게 맡긴 제작·편집·번역·디자인 등의 비용 |
| AD_PROMOTION | 광고·홍보: 내 채널·영상을 홍보하려고 지불한 광고비 |
| OTHER | 기타: 용도를 알지만 기존 범주 밖인 거래. 현재 법률 상담·기장·교육·서류 발급·보험 사례 사용 |
| UNCLASSIFIED | 미분류: 정보 부족·판단 보류. 임의의 정답 학습 클래스로 넣지 않음 |

위 기준은 서비스 분류 기준이며 세법상 경비 인정 여부를 뜻하지 않는다. 새 범주를 만들거나 기존 범위를 넓혀야 할 때는 사용자와 먼저 합의한다.

## 5. 최신 확장 초안 v4

기존 대표 설명 180개 + 추가 설명 185개 = **365개**다. v3의 540행보다 적어 보여도 v4는 `결제`, `비용 지급` 같은 접미사 변형으로 행 수를 늘리지 않았다. 같은 뜻의 다른 표현은 남아 있으므로 365개의 독립적인 거래 유형은 아니다.

| 범주 | 전체 설명 수 |
| --- | ---: |
| 소프트웨어 | 45 |
| 하드웨어 | 45 |
| 통신비 | 40 |
| 교통비 | 40 |
| 소모품·소품 | 45 |
| 공간 대여 | 40 |
| 외주비 | 40 |
| 광고·홍보 | 40 |
| 기타 | 30 |

- `labeled_candidates.csv`: description·category_code 및 관리용 sample_id·group_id·review_status. 모두 PENDING이며 모델에는 설명만 입력한다.
- `needs_info.csv`: 명확히 정보 부족인 설명 10개. 특정 정답 학습에 사용하지 않는다.
- `review_cases.csv`: 아래 경계 사례 8개를 **정답 코드 없이** 따로 보관한다.
- `manifest.json`: 버전·출처·건수·미분할·training_ready=false 기록. 수동 CSV 수정이 자동 반영되는 파일은 아니다.

보류 사례: 장비 대여, 게임 아이템, 리뷰용 화장품, 촬영용 의상, 장비 수리, 차량 대여, 의미가 불명확한 인터넷 비용, 수입·지출 의미가 불명확한 광고비 정산. 기존 범주에 억지로 넣지 않는다.

자체 점검은 필수값·ID·정규화 중복·코드·정답 충돌·재현성·덮어쓰기 방지와 기존 데이터/모델 보존을 확인했다. 의미상 정답의 완전성·실제 성능까지 보장하는 검증은 아니다.

## 6. 집 PC에서 재현하기

생성 CSV와 모델은 Git에서 제외된다. `.venv`도 PC마다 새로 만든다. 생성 코드·문서가 집 PC에 전달됐는지 먼저 확인한다. 아래는 **프로젝트 최상위 PowerShell** 기준이다.

```powershell
# 집 PC에 Python 3.14가 설치돼 있어야 한다.
py -3.14 -m venv ml/.venv
.\ml\.venv\Scripts\Activate.ps1
```

이미 가상환경이 있다면 생성 명령은 생략한다. 더미 생성은 Python 표준 라이브러리만 사용하므로 패키지 설치 없이 실행 가능하다.

```powershell
# 최신 확장 초안 생성 — 기본 옵션 없는 실행과 구분한다.
python ml/scripts/generate_dummy.py --expanded-draft
```

동일 출력 파일이 이미 있으면 기본 실행은 중단한다. 재생성 시 **검토한 CSV를 먼저 보존**한 후에만 `--overwrite`를 추가한다.

```powershell
python ml/scripts/generate_dummy.py --expanded-draft --overwrite
```

기존 v1·v2·v3를 집에서 다시 만들기 위해 최신 생성 코드의 버전명만 바꾸지 않는다. 각 시점 코드와 내용이 달라 과거 평가 자료를 재현했다고 보장할 수 없다. 필요한 과거 자료는 별도 보존본 또는 해당 시점 Git 코드를 사용해야 한다.

학습 패키지 설치는 필요할 때 `python -m pip install -r ml/requirements.txt`로 진행한다. **현재 v4를 생성한 뒤 바로 split_expense_data.py나 train_expense.py를 실행하면 안 된다.** 두 파일은 여전히 v3 경로·분할 기준을 사용한다.

## 7. 다음 작업 순서

1. 최신 확장 코드·문서가 있는지, 현재 브랜치·파일 상태부터 확인한다.
2. v4의 `EXTRA_SEEDS`를 기준으로 새로운 거래 설명을 보완한다. 기존 9개 범주 안에서 명확한 설명을 작성하고, 새 범주·애매한 정답은 별도 보류한다. 사용자는 매 행 승인 없이 자체 점검한 초안을 만드는 것을 허용했다. 억지로 건수를 채우지 않는다.
3. 생성 전후 정규화 중복·상충 정답·단순 표현 반복을 점검한다. 단순 분야명/접미사 변경은 새로운 유형으로 과장하지 않는다. 원본 설명과 그룹의 출처를 유지한다.
4. 샘플을 늘린 뒤 재생성한다. 사용자에게 카테고리별 건수·대표 설명·애매한 사례만 요약해 보고한다. 사용자가 요청하기 전에는 학습·커밋·push하지 않는다.
5. 학습 단계로 넘어갈 때 v4용 분할을 별도로 설계한다. 기존 FAMILIES는 v3 전용이라 번호만 늘려 재사용하지 않는다. 학습에 주요 거래 유형이 남는지와 비슷한 자료의 평가 유입을 함께 점검한다.
6. 사용자가 실행할 명령을 먼저 안내하고 결과를 같이 본다. 점수를 높이기 위해 test를 보고 자료·설정을 바꾸지 않는다.

**평가 보호:** 이번 추가 설명을 만들 때 기존 시험 파일을 참고하지 않았고 학교 PC의 기존 자료는 변경하지 않았다. 그러나 v4는 기존 대표 설명도 포함하므로 과거 평가 샘플과 겹칠 수 있다. v4 전체를 학습한 뒤 기존 test로 채점하면 안 된다. 다음 분할 때 기존 평가 자료와 겹치는 원문·유사 그룹을 학습에서 제외하거나, 새 평가 버전을 별도로 정해 이전 점수와 직접 비교하지 않는다. 시험 자료를 보호할 수 없다면 그 한계를 먼저 설명한다.

## 8. 서비스 연결·재학습 합의

`파일 추출 → 설명으로 분류 → 기존 화면에서 사용자 지정/건너뛰기 → 세금계산 클릭 → 전체 거래 저장 + 사용자 지정 학습 후보 별도 저장` 흐름이다.

- 학습 후보에는 수입/지출 구분·원본 거래 ID·설명·사용자 카테고리·학습 반영 상태를 보관한다.
- 자동 추천 유지·미분류 건너뛰기는 DB에 저장하지만 학습 후보에서 제외한다.
- 후보도 즉시 정답으로 학습하지 않는다. 모호한 설명은 제외하고 검토한 자료로 별도 재학습한다. 설명 보완을 사용자에게 강제하지 않는다.
- 학습·평가가 안정된 뒤 스케줄러를 검토한다. 지금 대화에서 전체 자동 재학습·API·DB 연결을 구현한 것은 아니다.

상세 기준은 [루트 설계 명세](../../docs/creator-tax-dummy-format.md), 파일 역할은 [파일 안내](file-guide.md)를 참고한다.

## 9. 다음 대화에 붙일 문장

> `ml/docs/home-handoff.md`를 먼저 읽어줘. 지출 설명만 사용하는 분류 모델의 더미데이터를 보완하던 중이고, 수입은 나중에 할 거야. 기존 카테고리를 유지하면서 v4 초안의 설명을 다양하게 늘리고 자체 점검해줘. 억지인 거래는 정답을 붙이지 말고 보류해줘. 기존 평가 데이터는 보호하고, 폴더 구조 변경·학습·커밋·push는 먼저 설명해줘.
